# デザイン

HINAMI の見た目の決まりの入口。どの資料に何があり、どれを正とするかを示す。

> **現在地 (2026-11-28)**: 方向性、ロゴ、デザイントークン、ブランドの金を決めた。次は、残りの画面を同じ方向で起こし、PHASE 1 の実機で確かめる。トークンを `packages/` にコードとして置くのは、アプリを作り始めるとき。

## 直すときの順番

1. 決まりが変わったら、正の文書 (`direction.md`、`tokens.md`、`logo/README.md`) を直す。値は `tokens.md` を正とし、ほかの文書に値を書くのは理由の説明に要るときだけにする
2. 画面イメージやロゴの SVG を合わせ、[`tools/`](tools/README.md) でスライドの画像を作り直す
3. スライドを直して公開し直す ([`deck/README.md`](deck/README.md))
4. 外した案は [`history.md`](history.md) に移す。判断待ちが決まったら [`../open-questions.md`](../open-questions.md) から消す

## 決めていないこと

- 文書をまたぐもの (残りの画面、ふだんの写真での見え方、ロゴの受け取られ方、空の画面、マップ) は [`../open-questions.md`](../open-questions.md) の「デザイン」
- 各文書の細かいものは、それぞれの「決めていないこと」
