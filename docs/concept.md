# プロダクトコンセプト

HINAMI (日次 / ひなみ) は、口にする食と飲みを 1 品ずつ記録する個人向けスマホアプリ。覚えておきたい一皿だけでも、口にするすべてでも残せる。究極は、自分の好みを誰よりも知っていて、記憶している記録帳になる。
「人に見せる食レビュー」ではなく「自分のための、育つ食と飲みの記録帳」(2026-11-28 に「食と酒」から改めた。酒を飲まない人にも届くように)。自分だけの「おいしかった」を集めていく。

提案書 (スライド) は [`concept-deck/`](concept-deck/README.md) にある。2026-11-28 に、UX の決定と 3 つの施策を反映して書き直した。構想段階の版は [`references/slides/concept-deck/`](references/slides/concept-deck/) に残している。

## 確定している前提

| 項目               | 内容                                                                                                                                                                                                                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 何を記録するか     | 口にする食と飲みなら、何でも記録できる。覚えておきたい体験 (美味しい店、頑張った自炊、良い一杯) だけでも、日常の食事まで含めたすべてでもよい。すべて記録することは求めない。究極は、口にしたものすべてを残し、自分の好みを誰よりも知っていて記憶しているアプリになれる (2026-11-28、作り手の判断。以前は「毎日の全記録ではなく、覚えておきたい体験」としていた) |
| 必須の情報         | 写真だけ。場所は撮影位置から自動で入る。品名は分からないことが多いため、任意のメモにする。記録できる食の種類は限定しない                                                                                                                                                                                                                                        |
| 食と飲み           | 1 つのアプリで記録する。食事では両方を記録するのに、アプリが分かれていると使いづらいため                                                                                                                                                                                                                                                                        |
| 外食と家ごはん     | どちらにも寄せない。何を記録するかは、その人が決める (2026-11-28、作り手の判断)。外食も、自炊・惣菜・出前の家ごはんも、同じように残せる                                                                                                                                                                                                                         |
| 記録の単位         | 1 品ずつ。まとめて登録するとは限らない。同じ食事の記録は時刻と場所で自動にまとまる (詳細は [`ux/recording.md`](ux/recording.md))                                                                                                                                                                                                                                |
| 種類の判定         | 画像判定の AI がその場で種類 (ラーメン、日本酒、コーヒーなど) を付ける (1 秒未満を目指す)。1 枚に複数写っていれば複数付く。間違っていたらその場で手で直す。食・飲は種類の上の大カテゴリとして裏で持ち、利用者には登録させない                                                                                                                                   |
| 記録の入り口       | アプリで撮る、撮った写真から選ぶ、の両方。その場でも、落ち着いてからでも記録する。撮影場所から店を推定する。ロック画面などから HINAMI のカメラを開けるようにしたい (作れるかは確かめる。[`ux/navigation.md`](ux/navigation.md))                                                                                                                                 |
| 記録の手軽さ       | シャッターだけで記録になる (撮ったら残る)。記録を残すボタンは右下に浮かせて置き、どの画面からでもいつもの記録までが簡単で気軽であること。ここが重いと使われない                                                                                                                                                                                                 |
| 検索性             | 今までの飲食を、いろんな角度で探せることを売りにする。記録のタブで、カレンダー・種類・フリーワード・マップから探す (詳細は [`ux/history.md`](ux/history.md))。SNS では写真を後から見返しづらく、場所も分からず、分類もできない、という不満に応える                                                                                                              |
| 形態               | スマホのネイティブアプリ。最初は日本向け                                                                                                                                                                                                                                                                                                                        |
| メインターゲット   | 普段から食と飲みにこだわる、少し余裕のある大人 (30〜40 代を想定。2026-11-28 に「食と酒」から改めた)                                                                                                                                                                                                                                                             |
| 偏らせない         | 特定の種類に寄せない。酒を飲まない人も、ワイン・ウイスキー・日本酒などが好きな人も、同じ厚さの体験と価値を受け取れるようにする (2026-11-28、作り手の判断)。作り手の好み (日本酒) を前提にしない                                                                                                                                                                 |
| 公開時の打ち出し方 | 種類で絞らず、種類を問わない価値 (撮るだけで残り、好みを知ってくれる) で打ち出す (2026-11-28、作り手の判断)。構想のころの「料理か地酒か」、レビューの「地酒 × 料理」は採らない                                                                                                                                                                                  |
| 目指す水準         | ただの記録ではなく、今までにない最先端で質の高いアプリ。記録アプリにイノベーションを起こす (作り手の思い。2026-11-28)。最新の手法や世の中の成功事例を取り入れる                                                                                                                                                                                                 |
| 最重要             | 作り手自身がドッグフーディングできること                                                                                                                                                                                                                                                                                                                        |
| 収益目標           | まず 1 円以上                                                                                                                                                                                                                                                                                                                                                   |

## 体験

食べる・飲む → 残す → 比べる → 育つ → 使う (次の店を選ぶ、人に勧める、見返す)

- **比べる**: 点数はつけない。「どっちが好き?」の 2 択に答えると、種類別の自分ランキングが育つ (米国 Beli の型)。食べたあと、次にアプリを開いたときにホームのカードで 1 問だけ聞き、二分で挿し込んで順位を決める (詳細は [`ux/compare.md`](ux/compare.md))
- **続けたくなる仕組み**: 2 択ランキング、実績、食べた場所のマップ (記録のタブの中)、年間ふりかえり (予定)。毎日の連続記録と総件数は使わない (義務感は逆効果)。酒蔵などの協賛ラリーは、STEP 2 の別の仕組みにする。友人との好みの一致度は未決
  - 記録の直後に HINAMI が返すのは実績。記録が積み重なった節目として作り、ユーモアのある名前と淡々とした条件で知らせる。アプリを出し直さずに運営の管理画面から足せるようにする (詳細は [`ux/achievements.md`](ux/achievements.md))
- **記録が好みを語る**: 種類ごとに、自分の記録から好みを言葉にし、次に試す方向を出す。店や銘柄の名前は出さない。まだ行っていない店の提案は MVP に入れない (詳細は [`ux/taste.md`](ux/taste.md))
- **つながる**: 最初の版から入れる (PHASE 1 から家族と使い、限定テストで知り合いに広げるため)。ただし一人で使っても成り立つことが前提で、つながりは上乗せにする。つながるのは、お互いに承認した友だちだけ。全体公開とフォローは入れない。公開範囲は食事ごとに、自分だけ / 友だち から選ぶ。既定は設定で選べ、最初は自分だけ。友だちに見えるのは写真とメモだけ (詳細は [`ux/connect.md`](ux/connect.md))。いいね数は前面に出さない。まずはお試しのおまけとして、友だち専用のタブに閉じる。うまくいけば、メインの機能に少しずつ出していく
  - HINAMI の中で、友だちに食事をシェアし、スタンプとメッセージを受けられる。やりとりは友だちごとに 1 つのスレッドで続き、どの食事への反応かが分かる
  - ストーリーなど今の SNS へは、端末に残った写真から上げる (HINAMI で撮った写真は端末にも残す)

参考事例: Beli (2 択ランキング)、Untappd (バッジ・収集)、Vivino (写真から記録)、SARAH (一皿単位)

## 収益

- **STEP 1**: 個人課金のプレミアム、月 800 円 (仮)
- **STEP 2**: 酒蔵・ワイナリー・レストランの協賛ラリー
- **STEP 3**: 体験への送客
- 目安は有料会員約 150 人で月 10 万円 (仮定)。広告は入れない

## 進め方

期間ではなく関門で進む。

| フェーズ   | 内容                   | 関門                                                                                |
| ---------- | ---------------------- | ----------------------------------------------------------------------------------- |
| PHASE 1    | 家族と使い込む         | 作り手が 4 週間使い、このまま使い続けたいと思えた。数えずに、作り手の手応えで決める |
| 限定テスト | 知り合いに使ってもらう | 作りながら決める                                                                    |
| PHASE 2    | 公開と最初の 1 円      | 継続率 30% 以上 (仮)                                                                |
| PHASE 3    | 収益を広げる           | —                                                                                   |

- PHASE 1 と限定テストは、Expo のアプリを TestFlight で入れて使う ([ADR-0002](adr/0002-phase1-on-testflight.md))
- PHASE 1 の合否は、記録漏れや件数を数えず、作り手の手応えで決める (2026-11-28、作り手の判断)。アプリが自動で残せる数字 (比べるの答えた率など) は、見返しの材料にとどめ、合否には使わない
- PHASE 1 から、公開の最初の版に入れる機能を友だちの機能まで作り、作り手と家族で使う (2026-11-28、作り手の判断)。限定テストでは知り合いに広げる。合否は作り手の手応えで決める
- 運営の管理画面は、利用者が使うものではないので PHASE 1 では作らない。ロック画面などから開くカメラは、技術の確認で作れると分かれば入れる
- テストの段 (PHASE 1、限定テスト) の進め方、関門、測るものは詳しく詰めず、作りながら更新する。先に、サービスの本質 (体験と価値) を詰める (2026-11-28、作り手の判断)

## ほかのアプリとのつながり

酒に絞った姉妹アプリ (仮に「HINAMI for sake」) を作ることがあれば、同じアカウントで記録を共有できるようにする (2026-11-27、作り手の希望)。

- 記録とアカウントはサーバーに置き、HINAMI 以外のアプリからも、同じアカウントで読み書きできる形にしておく
- 種類の一覧 (3 段) も共有する。姉妹アプリが銘柄や蔵などの項目を足すときは、HINAMI の記録を壊さずに足せる形にする
- 姉妹アプリは、HINAMI と同じ Apple の開発者アカウントで出す。Sign in with Apple が返す利用者の番号は開発者アカウントごとに違うので、別のアカウントで出すと同じ人だと分からなくなる

## サービス名

HINAMI (日次 / ひなみ)。日付順に一皿と一杯が並び、自分の食の暦になる、という意味づけ。
ストアでは「HINAMI - 食と飲みの記録帳」のように説明を添える想定。
