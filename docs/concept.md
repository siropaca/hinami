# プロダクトコンセプト

HINAMI (日次 / ひなみ) は、食と飲みの「覚えておきたい体験」を記録する個人向けスマホアプリ。
「人に見せる食レビュー」ではなく「自分のための、育つ食と酒の記録帳」。自分だけの「おいしかった」図鑑をつくる。

提案書の全体は [`references/slides/concept-deck/`](references/slides/concept-deck/) を参照 (`view.html` をブラウザで開く)。

## 確定している前提

| 項目             | 内容                                                                                                                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 何を記録するか   | 毎日の全記録ではなく、写真に撮って残したくなる「覚えておきたい」食と飲みの体験 (美味しい店、頑張った自炊、良い一杯)。コンビニ弁当などの日常食は任意                                                                                        |
| 必須の情報       | 写真だけ。場所は撮影位置から自動で入る。品名は分からないことが多いため、任意のメモにする。記録できる食の種類は限定しない                                                                                                                   |
| 食と飲み         | 1 つのアプリで記録する。食事では両方を記録するのに、アプリが分かれていると使いづらいため                                                                                                                                                   |
| 記録の単位       | 1 品ずつ。まとめて登録するとは限らない。同じ食事の記録は時刻と場所で自動にまとまる (詳細は [`ux/recording.md`](ux/recording.md))                                                                                                           |
| 種類の判定       | 画像判定の AI がその場で種類 (ラーメン、日本酒、コーヒーなど) を付ける (1 秒未満)。1 枚に複数写っていれば複数付く。間違っていたらその場で手で直す。食・飲は種類の上の大カテゴリとして裏で持ち、利用者には登録させない                      |
| 記録の入り口     | アプリで撮る、撮った写真から選ぶ、の両方。その場でも、落ち着いてからでも記録する。撮影場所から店を推定する                                                                                                                                 |
| 記録の手軽さ     | 記録を残すボタンは右下に浮かせて置き、どの画面からでもいつもの記録までが簡単で気軽であること。ここが重いと使われない                                                                                                                       |
| 検索性           | 今までの飲食を、いろんな角度で探せることを売りにする。記録のタブで、カレンダー・種類・フリーワードから探す (詳細は [`ux/history.md`](ux/history.md))。SNS では写真を後から見返しづらく、場所も分からず、分類もできない、という不満に応える |
| 形態             | スマホのネイティブアプリ。最初は日本向け                                                                                                                                                                                                   |
| メインターゲット | 普段から食と酒にこだわる、少し余裕のある大人 (30〜40 代を想定)                                                                                                                                                                             |
| 最重要           | 作り手自身がドッグフーディングできること                                                                                                                                                                                                   |
| 収益目標         | まず 1 円以上                                                                                                                                                                                                                              |

## 体験

食べる・飲む → 残す → 比べる → 育つ → 使う (次の店を選ぶ、人に勧める、見返す)

- **比べる**: 点数はつけない。「どっちが好き?」の 2 択に答えると、種類別の自分ランキングが育つ (米国 Beli の型)。食べたあと、次にアプリを開いたときにホームのカードで 1 問だけ聞き、二分で挿し込んで順位を決める (詳細は [`ux/compare.md`](ux/compare.md))
- **続けたくなる仕組み**: 2 択ランキング、実績 (クエスト・スタンプカード・バッジ)、食べた場所のマップ、スタンプラリー、年間ふりかえり、友人との好みの一致度。毎日の連続記録は使わない (義務感は逆効果)
  - 記録の直後に HINAMI が返すのは実績。記録が積み重なった節目として作り、アプリを出し直さずに運営の管理画面から足せるようにする (詳細は [`ux/achievements.md`](ux/achievements.md))
- **つながる**: 最初の版から入れる (限定テストで家族や知り合いと使うため)。ただし一人で使っても成り立つことが前提で、つながりは上乗せにする。つながるのは、お互いに承認した友だちだけ。全体公開とフォローは入れない。公開範囲は食事ごとに、確認カードで自分だけ / 友だち から選ぶ。既定は友だち。友だちに見えるのは写真とメモだけ (詳細は [`ux/connect.md`](ux/connect.md))。いいね数は前面に出さない。まずはお試しのおまけとして、友だち専用のタブに閉じる。うまくいけば、メインの機能に少しずつ出していく
  - HINAMI の中で、友だちに食事をシェアし、スタンプとメッセージを受けられる。やりとりは友だちごとに 1 つのスレッドで続き、どの食事への反応かが分かる
  - ストーリーなど今の SNS へは、端末に残った写真から上げる (HINAMI で撮った写真は端末にも残す)

参考事例: Beli (2 択ランキング)、Untappd (バッジ・収集)、Vivino (写真から記録)、SARAH (一皿単位)

## 収益

- **STEP 1**: 個人課金のプレミアム、月 800 円 (仮)
- **STEP 2**: 酒蔵・ワイナリー・レストランの協賛ラリー
- **STEP 3**: 体験への送客
- 目安は有料会員約 150 人で月 10 万円 (仮定)。広告は入れない

## 進め方

期間ではなく関門で進む。

| フェーズ   | 内容                         | 関門                                                |
| ---------- | ---------------------------- | --------------------------------------------------- |
| PHASE 1    | 自分で使い込む               | 作り手が 4 週間、覚えておきたい食をすべて記録できた |
| 限定テスト | 家族や知り合いに使ってもらう | 未定 (PHASE 1 で測るものと一緒に決める)             |
| PHASE 2    | 公開と最初の 1 円            | 継続率 30% 以上 (仮)                                |
| PHASE 3    | 収益を広げる                 | —                                                   |

- PHASE 1 と限定テストは、Expo のアプリを TestFlight で入れて使う ([ADR-0002](adr/0002-phase1-on-testflight.md))
- 限定テストでは、家族や知り合いと友だちの機能を使う。そのため、友だちの機能は限定テストまでに作り、公開の最初の版にも入れる (作り手の判断)

## ほかのアプリとのつながり

酒に絞った姉妹アプリ (仮に「HINAMI for sake」) を作ることがあれば、同じアカウントで記録を共有できるようにする (2026-11-27、作り手の希望)。

- 記録とアカウントはサーバーに置き、HINAMI 以外のアプリからも、同じアカウントで読み書きできる形にしておく
- 種類の一覧 (3 段) も共有する。姉妹アプリが銘柄や蔵などの項目を足すときは、HINAMI の記録を壊さずに足せる形にする
- 姉妹アプリは、HINAMI と同じ Apple の開発者アカウントで出す。Sign in with Apple が返す利用者の番号は開発者アカウントごとに違うので、別のアカウントで出すと同じ人だと分からなくなる

## サービス名

HINAMI (日次 / ひなみ)。日付順に一皿と一杯が並び、自分の食の暦になる、という意味づけ。
ストアでは「HINAMI - 食と酒の記録帳」のように説明を添える想定。

商標などの確認状況は [`open-questions.md`](open-questions.md) を参照。
