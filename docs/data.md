# 記録にためるもの

> **状態: 方針を決めた (2026-11-28)**。原則、ためるもの、店の名前の持ち方、使い方の記録、運営が使うときの同意を決めた。店の情報の提供元は、技術の確認で決める。

## 目的

記録をどの場面で活かすか (好みを返す場面など) は、データをためながら、作りながら確かめる (2026-11-28、作り手の判断。[`ux/taste.md`](ux/taste.md))。だから今は、まだ使わないものも、あとで新しい使い方や新しい AI に活かせる形で残しておく。何年も残る記録帳として、あとから取り戻せないものを取りこぼさないことを優先する。

## 原則

| 原則                                                                     | 理由                                                                                                                                                                                                   |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 元を残す。写真、撮った時刻と位置、気持ちと比べるの答えは、加工せずに残す | 種類の判定、名前の読み取り、店の推定、順位、好みのことばは、元があれば新しい AI でいつでも作り直せる。元は、あとから取り戻せない                                                                       |
| 利用者が決めたことは、AI が出したものと分けて残す。直しても上書きしない  | 直した種類、選んだ店、入れた名前、「比べられない」、「違う」は、その人にとっての正解。AI の版が変わっても消えない。何を何に直したかが残れば、AI がどれだけ当たったかも測れる                           |
| あとから外から引けるものは残さない                                       | 天気、祝日、店の評価や営業時間は、時刻・位置・店の ID から引ける。ただし店の名前は、閉店すると引けなくなりうるので別に扱う (下の「店の名前」)                                                          |
| 利用者が知らないものをためない                                           | 写真の背景の文字 (レシート、人の名前)、端末の写真、ずっと続く位置の履歴は持たない。持つのは、利用者が残したものと、そこからすぐ分かるものだけ                                                          |
| ためたものは利用者のもの                                                 | アカウントを消せば、すべて消える ([`ux/onboarding.md`](ux/onboarding.md))。姉妹アプリからも同じアカウントで読める形にする ([`concept.md`](concept.md))。運営が使うときの決まりは下の「運営が使うとき」 |

## ためるもの

| まとまり | もの                 | 決まり                                                                                                                                                                                                                                                                              |
| -------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 品       | 写真                 | 写真は食事に属し、品は写真と、写真の中の範囲を指す (0 枚以上。[`ux/recording.md`](ux/recording.md) の「品と写真」)。撮ったときのまま残す (大きさ、形式、写真に埋め込まれた撮影時刻や位置の情報も)。表示用に縮めた版は、作り直せるものとして持つ。費用の目安は下の「写真を残す費用」 |
| 品       | 名前を読む写真       | 写真と同じ                                                                                                                                                                                                                                                                          |
| 品       | 時刻と位置           | 写真の撮影時刻と位置、位置の精度。位置がない写真は、ないまま残す。写真のない品は、残したときの端末の時刻と位置か、足した食事のもの。どこから来たか (写真、端末、食事、利用者が選んだ) も残す                                                                                        |
| 品       | 一緒に写っているもの | AI が出したもの (AI の版) と、利用者が品にしたもの                                                                                                                                                                                                                                  |
| 品       | 残し方               | その場で撮った、写真から選んだ、ロック画面などから開いた。食べる前か後かの手がかりになる (比べるの聞く時機、[`ux/compare.md`](ux/compare.md))                                                                                                                                       |
| 品       | 種類                 | AI が付けたもの (候補、確からしさ、AI の版、日時) と、利用者が直したもの。直しても AI が付けたものは消さず、何を何に直したかを別に残す。細かい種類も同じ                                                                                                                            |
| 品       | 名前                 | メモに入れた名前と、その読み。見送った候補は印だけを持ち、中身は持たない。読み取った文字の全文は持たない (写真から読み直せるため。[`ux/history.md`](ux/history.md) の「名前の候補」)                                                                                                |
| 品       | メモ                 | 書いたまま                                                                                                                                                                                                                                                                          |
| 品       | 買った店             | 買ってきたものだけ ([`ux/recording.md`](ux/recording.md) の「買ってきたもの」)                                                                                                                                                                                                      |
| 食事     | 時刻と場所           | 場所は、店、家、店ではない、地域のどれか。推定のままか、利用者が選んだかも残す。店の残し方は下の「店の名前」                                                                                                                                                                        |
| 食事     | 食事のメモ、シェア   | 書いたまま、選んだまま                                                                                                                                                                                                                                                              |
| 食事     | 食事の写真           | メニュー、外観、レシートなど、品にしていない写真。品の写真と同じく、撮ったまま残す                                                                                                                                                                                                  |
| 気持ち   | 答え                 | 品ごと、食事ごとに、いつ、どれを選んだか (大好き / 好き / ふつう / 合わなかった)。付け直しても前の答えを残す。カードを出したのに答えなかったことも残す ([`ux/compare.md`](ux/compare.md))                                                                                           |
| 比べる   | 答え                 | 1 問ずつ残す: いつ、どの 2 品、どちらを選んだか、または「比べられない」。順位は、気持ちと答えから作り直せるものとして持つ ([`ux/compare.md`](ux/compare.md))                                                                                                                        |
| 比べる   | 手で並べ替えたこと   | いつ、どの品を、どこからどこへ                                                                                                                                                                                                                                                      |
| 好み     | 「違う」と言われた文 | 好みのことばのうち、利用者が「違う」で消した文と、その根拠にした記録。同じことを二度言わないため。好みの材料にもなる ([`ux/taste.md`](ux/taste.md))                                                                                                                                 |
| 好み     | 好みに入れない記録   | 「この記録は好みに入れない」とした記録                                                                                                                                                                                                                                              |
| 家       | 覚えた家             | 位置。消せる ([`ux/settings.md`](ux/settings.md))                                                                                                                                                                                                                                   |
| 思い出   | 思い出に出さないもの | 食事・期間・店の単位で。戻せる ([`ux/memory.md`](ux/memory.md))                                                                                                                                                                                                                     |
| 思い出   | 帳面に足した言葉     | 帳面の頁に足した見出しや一言。帳面そのものは、記録から作り直せるものとして持つ                                                                                                                                                                                                      |
| 同意     | 同意したこと         | 使い道ごとに、いつ、どの版の文言に同意したか。あとで止めたときも残す                                                                                                                                                                                                                |

## 写真を残す費用

写真を縮めずに残すと、あとで新しい AI がラベルの小さな文字まで読み直せる。大手も元の写真を残している (Google フォトの「元の画質」、iCloud の写真、Day One)。費用は、課金の額と比べて小さい。

| 1 日 3 枚 (年 1,095 枚) | 1 年分の量  | 1 年分を 1 年置く費用 (Cloudflare R2) |
| ----------------------- | ----------- | ------------------------------------- |
| 撮ったまま (1.5〜3 MB)  | 1.6〜3.3 GB | 1 人 $0.29〜0.59                      |
| 長辺 2048px に縮める    | 0.4〜1.1 GB | 1 人 $0.08〜0.20                      |

- 量は年ごとに積み上がる。撮ったままを 5 年続けると、5 年目は 1 人年 $1.5〜3 になる
- R2 は 1 GB・1 か月 $0.015 (あまり読まない保存は $0.01)、外への転送は無料。S3 の東京は $0.025
- 縮めた版の量は推定で、測っていない

出典: [Google フォトの画質](https://support.google.com/photos/answer/6220791)、[iCloud の写真](https://support.apple.com/105061)、[Day One の写真](https://dayoneapp.com/guides/tips-and-tutorials/photo-optimization/)、[Cloudflare R2 の料金](https://developers.cloudflare.com/r2/pricing/)

## 店の名前

閉店した店も、何年たっても名前で思い出せるようにする。気に入っていた店ほど、閉店したあとに見返したくなるため。店の情報の提供元を選ぶ条件にする ([`open-questions.md`](open-questions.md) の「技術」)。

| 提供元                                        | 店の名前を期限なく持てるか                                                                   | 閉店した店の ID                                               |
| --------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Apple MapKit                                  | 持てない。持てるのは Place ID だけ (開発者の規約 Attachment 6 の 2.5)                        | 閉店して長く経つと引けなくなる、と公式の文書にある            |
| Google Places                                 | 持てない。店の名前と住所の保存をはっきり禁じている (規約 3.2.3(a))。持てるのは place_id だけ | 閉店や移転で失効しうる。12 か月を超えた ID は更新を勧めている |
| Foursquare (API)                              | 持てない。持てるのは店の ID と写真の ID だけ                                                 | 確かめられなかった                                            |
| オープンデータ (OpenStreetMap、Overture など) | 持てる。帰属の表示が要る                                                                     | 自分で名前を持つので、引き直さなくてよい                      |

- 今の案: 店の正本をオープンデータに置き、名前・住所・位置・業種を記録に写して持つ。Apple は地図の表示と Place ID に使い、引ければ最新の名前を出す。引けなくなったら、記録に写した名前を出す
- 日本の飲食店をオープンデータがどれだけ網羅しているかは確かめていない。Apple や Google より薄い見込み。技術の確認で、店の推定の当たり方と一緒に測る
- Apple の名前を記録に自動で写すことはしない。規約に触れるおそれがあるため

出典: [Apple 開発者の規約](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/)、[MapKit の Place ID](https://developer.apple.com/documentation/mapkit/identifying-unique-locations-with-place-ids)、[Google Maps Platform の規約](https://cloud.google.com/maps-platform/terms)、[Places の place_id](https://developers.google.com/maps/documentation/places/web-service/place-id)、[Foursquare の利用の決まり](https://docs.foursquare.com/fsq-developers-places/reference/usage-guidelines)、[OpenStreetMap のジオコーディングの指針](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Geocoding_-_Guideline)、[Overture の帰属](https://docs.overturemaps.org/attribution/)

## 使い方の記録

どの機能がどれだけ使われるかを、データを活かせるところを探す材料にする。

- 目的を決めた最小の項目だけを、自前のサーバーに残す (画面を開いた、検索した、気持ちに答えた、自分から比べたなど)。解析の SDK は入れない。第三者に渡さないので、ATT (追跡の許可) は要らない
- アカウントと結びつける。好みの違う人ごとに使い方を見るため。App Store のプライバシーの表示では「製品の操作」「検索履歴」を「ユーザーにリンク」として出し、利用目的に「使い方を分析すること」まで書く
- 残す期間を決める (今の案: 1 年)

## 運営が使うとき

利用者が直した結果や写真を、HINAMI 全体の判定 (種類、名前の読み取り) を良くするのに使うかは、一度だけはっきり聞く (2026-11-28、作り手の判断)。日本の食の見分け (つけ麺とラーメンの境など) は、AI の提供元より利用者の直しで良くなるため。

| 項目     | 決まり                                                                                                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 聞くとき | 写真を AI に送る同意を取るとき、それとは別に「判定を良くするのにも使ってよいか」を選んでもらう。AI に写真を送らない作りになったときは、はじめて種類を直したときに聞く ([`ux/onboarding.md`](ux/onboarding.md)) |
| 既定     | どちらにも印を付けておかない。Apple が「Siri の改善」を最初に聞くのと同じ型                                                                                                                                    |
| 変える   | 設定からいつでも変えられる ([`ux/settings.md`](ux/settings.md))。止めたあとは、新しい記録を使わない                                                                                                            |
| 使うもの | AI が付けたものと、利用者が直したもの、その写真。顔と位置 (写真に埋め込まれた位置の情報を含む) は外す。メモ、食事のメモ、友だちとのやりとりは使わない                                                          |
| 渡す先   | 判定の AI を外の会社に頼むときは、その会社が自分の学習に使わないことを確かめる (個人情報保護委員会の注意喚起)                                                                                                  |
| 聞く理由 | 集めたあとに使い道を足すと、改めて同意が要る (App Store の審査ガイドライン 5.1.2(ii))。最初に決めておく                                                                                                        |

出典: [App Store の審査ガイドライン](https://developer.apple.com/app-store/review/guidelines/)、[個人情報保護法の Q&A](https://www.ppc.go.jp/personalinfo/faq/APPI_QA/)、[生成 AI の利用の注意喚起](https://www.ppc.go.jp/news/press/2023/230602kouhou/)

## 入れないもの

| もの                         | 理由                                                                                                                                                            |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 読み取った文字の全文         | 背景のレシートや人の名前まで入るため。メニューや看板の文字も、読んですぐ使い、残さない。写真を残すので、要るときに読み直せる ([`ux/history.md`](ux/history.md)) |
| 端末の写真                   | 写真を勝手に見られているようで怖いため (作り手の判断。[`ux/recording.md`](ux/recording.md))                                                                     |
| ずっと続く位置の履歴         | 撮ったときの位置だけで、場所と地域が分かる。それ以外の位置を持つ理由がない                                                                                      |
| 写真に写った顔を見分けた結果 | 誰と食べたかは、食事のメモに書けば足りる                                                                                                                        |

## 決めていないこと

- 店の情報の提供元 (技術の確認で、オープンデータの網羅と一緒に決める)
