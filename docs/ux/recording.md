# 記録の流れ (UX)

> **状態: 合意 (2026-11-26)**。ワイヤーフレームまで見て、この流れで進める。「案」はもうない。2026-11-27 に、記録の入り口を右下の ＋ に移し、保存したあとはトーストで知らせる形にした。買ったもの (まだ口にしていないもの) は記録しないことにした。2026-11-28 に、シャッターだけで記録になる形 (撮ったら残る) にした ([`../research/2026-11-28/README.md`](../research/2026-11-28/README.md) の施策 1)。同じ日に、買ってきたものは場所に買った店を選べるようにした (下の「買ってきたもの」)。同じ日に、品と写真の決まり (記録の単位) を決め、写真なしでも、料理でない写真も残せるようにした (下の「品と写真」)。
>
> ワイヤーフレーム (画面遷移図): [`recording-flow.html`](recording-flow.html)。ブラウザで開く。

## 目的

ホームからいつもの記録までを、簡単で気軽にする。ここが重いと使われない。
PHASE 1 の関門は、作り手が 4 週間使い、このまま使い続けたいと思えること ([`../concept.md`](../concept.md) の「進め方」)。

## 流れ

```
右下の [＋] (どの画面からでも。長押しで「写真なしで残す」)
 └─ カメラ ─ [シャッター] ─▶ その場で残り、もとの画面に戻る
     │                        トーストに「残しました」[直す][取り消す]
     │                        └─ [直す] ─▶ 確認カード
     ├─ [写真から選ぶ] (左下) ─▶ 確認カード / 確認 (複数枚) ─ [残す] ─▶ もとの画面
     └─ [写真なし] (右下) ─▶ 写真なしで残す ─ [残す] ─▶ もとの画面
```

- 画面の移動は、基本的にタブバーで行う
- 記録を残す入り口は、右下に浮かせた ＋ ボタン (2026-11-27 に、ホームのボタンから移した)。どの画面からでも記録を始められる。押すとすぐカメラが開き、写真から選ぶ入り口はカメラの左下に置く ([`navigation.md`](navigation.md))
- その場で撮っても、落ち着いてから写真から選んでも、同じ流れで記録できる
- 写真から選ぶ場合は、写真に残った位置と日時を使う
- アプリで撮った写真は、端末の写真アプリにも残す。ストーリーなどほかの SNS には、そこから上げる
- カメラと位置情報の許可は、はじめて ＋ を押したときに聞く。はじめて残したときのトーストでだけ、ヒントを 1 つ出す ([`onboarding.md`](onboarding.md))
- シャッターを押した時点で記録になる (2026-11-28、作り手の判断。撮ったら残る)。最短 2 タップ (＋ → シャッター)。記録漏れを減らすため。種類と場所は、保存のあとに AI と位置から付く
- 残したら、記録を始めた画面に戻る (2026-11-28、作り手の判断。カメラのままにして続けて撮る案は採らなかった)。ロック画面などから開いたときは、戻る画面がないのでホームに戻る
- 戻った画面に、トーストで「残しました」を出し、「直す」「取り消す」を置く。解除した実績と、はじめての種類も同じトーストに出す。タップは増やさない (詳細は [`achievements.md`](achievements.md))
- 確認カードは、直したいときだけ開く。開き方は、トーストの「直す」、食事の詳細の品、写真から 1 枚選んだとき
- ロック画面などから HINAMI のカメラを開けるようにする (作れるかは技術の確認で確かめる。[`navigation.md`](navigation.md))。そうすれば「コントロール → シャッター」で終わる

## 確認カード

直したいときに開く。撮って残した品は、開かなくても記録になっている。

```
写真                    [名前を読む写真を足す]
一緒に写っているもの: ビール [＋]   タップすると品になる
[ラーメン ▾]            AI が付けた種類。違えばタップで直す
場所 麺屋 ひかり ▾        推定に自信があるとき: 店名
    道玄坂・候補 3 件 ▾  自信がないとき: 地域名 (店を決め打ちしない)
シェア 友だち ▾          友だちがいるときだけ出す。食事ごと
メモ (任意)  候補: 特製醤油らーめん   写真の文字から読めたときだけ
```

AI や推定で入るもの (種類、場所、名前の候補) は、すべて同じ扱いにする。確認カードや食事の詳細で、違えば直せる。直さなくても残る。それとは別に、利用者に分類を登録させることはしない。

| 項目           | 決まり                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 必須の入力     | なし。写真だけで記録になる。写真がないときは、名前か種類のどちらかを入れる (下の「写真なしで残す」)                                                                                                                                                                                                                                                                                                                                                    |
| 種類           | 保存のあとに、画像判定の AI が付ける (1 秒未満を目指す。技術の確認で確かめる)。品の種類は 1 つ (主役)。ほかに写っている食べ物や飲み物は「一緒に写っているもの」として出し、タップで品にできる (下の「品と写真」)。間違っていたらその場で手で直す。種類は運営が持つ 3 段の一覧 (大分類 → 種類 → 細かい種類) から付き、確認カードには真ん中の「種類」を出す ([`kinds.md`](kinds.md))。食・飲はその上の大カテゴリとして裏で決まり、利用者には登録させない |
| 場所           | 下の「場所」を参照                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| メモ           | 任意。品名は分からないことが多いため、必須にしない。AI が写真の文字 (ラベル、メニュー、包装) から名前を読めたときは、メモの候補として出し、タップで入れられる。どの種類の品でも同じ (詳細は [`history.md`](history.md) の「名前の候補」)                                                                                                                                                                                                               |
| 前にも         | 同じ名前の品や同じ店に前にも出会っていたら、前回の時期と気持ち、何度目かを 1 行で出す。トーストには出さない ([`memory.md`](memory.md))                                                                                                                                                                                                                                                                                                                 |
| 名前を読む写真 | 品には、名前を読むための 2 枚目 (ラベル、札、包装) を足せる。瓶とグラスを撮っても、品は 1 つのまま (2026-11-28、施策 2)。名前を読む写真は、確認カードや品の画面の「名前を読む写真を足す」から撮ったものだけが品に付く。メニューや札を別に撮ったときは食事の写真になり、同じ食事の品の名前の候補に使う                                                                                                                                                  |
| シェア         | 友だちがいるときだけ出す。食事単位で、どの品のカードで変えても同じ食事の品すべてに効く。既定は設定で選べ、最初は「自分だけ」(詳細は [`connect.md`](connect.md))                                                                                                                                                                                                                                                                                        |
| 電波がない     | 保存を先に済ませ、電波が戻ったら判定する                                                                                                                                                                                                                                                                                                                                                                                                               |

## 品と写真 (記録の単位)

品は、口にした 1 つのもの (1 杯、1 皿、1 個、1 本)。写真は食事に属し、品は写真を 0 枚以上指す。1 枚の写真を、いくつかの品で分け合える (品ごとに、写真の中の範囲を持つ) (2026-11-28、作り手の判断。AI が品を自動で分ける形も検討し、下の理由で採らなかった)。

| 項目                 | 決まり                                                                                                                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 品を作る             | 利用者だけが作る。シャッター 1 回で、品は多くても 1 つ。「一緒に写っているもの」をタップしたとき、写真なしで残したときにも品ができる。AI は品を作らず、消さない                                                                                                     |
| AI がすること        | 1 枚を「品 (主役)」か「食事の写真」に振り分け、主役に種類を 1 つ付ける。ほかに写っている食べ物と飲み物を「一緒に写っているもの」として出す                                                                                                                          |
| 一緒に写っているもの | 確認カードと品の画面に出す。タップすると品になり、同じ写真を分け合う。トーストには出さない (そっと出すだけ)。居酒屋の卓や飲み比べを 1 枚で撮ったときに使う                                                                                                          |
| 品の種類             | 1 つ (主役の種類)。同じ品が 2 つのランキングに並ばないようにするため                                                                                                                                                                                                |
| 食事の写真           | メニュー、券売機、店の外観や看板、店の中、レシートなど、料理でも飲み物でもない写真。品にせず、食事に付ける。トーストは「残しました」と「食事の写真」(種類の名前と同じくラベルとして出す)、「品にする」「取り消す」。友だちには見せない ([`connect.md`](connect.md)) |
| 食事の写真の文字     | メニュー、券売機、レシートの文字は、同じ食事の品の名前の候補に使う。看板の文字は、店の候補が複数あるときに店を決めるのに使う。読んだ文字は残さない ([`../data.md`](../data.md))                                                                                     |
| 品のない食事         | 店の外観だけを撮ったときなど。食事として残り、あとから品を足せる。実績にも、外食の回数にも数えない                                                                                                                                                                  |
| 見誤ったとき         | 料理を食事の写真にしたら「品にする」、料理でない写真を品にしたら「品にしない」で直す                                                                                                                                                                                |

- AI に品を分けさせない理由: 撮ったら残る形では、多くの品が見直されない。AI が品を作ると、居酒屋の他人のジョッキ、家族の分のケーキ、写真付きのメニューから、食べていない品ができ、黙ってランキングと好みに混ざる。誤りは「品にならない」側に寄せ、あとから足せるようにする。品が利用者の操作でしか生まれないので、AI を替えても、気持ちと比べるの答えの行き先が変わらない
- 好みの違う 6 人 (ワインと日本酒、パンとケーキ、飲まずに家で作る、居酒屋で大人数、おまかせやコース、毎日のコーヒー) の目で、3 つの形を比べて決めた

### よくある場面

| 場面                    | 扱い                                                                                                                                                                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ラーメンとビールを 1 枚 | 品はラーメン。ビールは一緒に写っているもの。タップすればビールも品になる                                                                                                                                                                                 |
| 定食、セット            | 1 品。種類は主菜。ご飯、味噌汁、小鉢は一緒に写っているもの                                                                                                                                                                                               |
| 居酒屋の卓全体          | 品は主役の 1 皿。ほかの皿は、一緒に写っているものから品にする。他人の杯を勝手に品にしない                                                                                                                                                                |
| コース、おまかせ        | 撮るたびに 1 品。食事全体にも気持ちを付けられる ([`compare.md`](compare.md) の「食事の気持ち」)。品の画面の「1 品にまとめる」で、写真を何枚も持つ 1 品にできる。ホームの気持ちの問いでは、同じ食事の同じ種類は 1 品だけ聞く ([`compare.md`](compare.md)) |
| 同じものを何杯も        | 撮るたびに別の品。品の画面の「前の品にまとめる」でまとめられる。実績は、同じ食事の同じ種類を 1 回と数える ([`achievements.md`](achievements.md))                                                                                                         |
| 瓶とグラス              | 1 品。瓶は名前を読む写真として足す                                                                                                                                                                                                                       |
| 大皿を取り分けた        | 1 品                                                                                                                                                                                                                                                     |
| 撮影できない店          | 外でのれんや看板を撮って店を決め (食事の写真になる)、中で食べた品を写真なしで足す                                                                                                                                                                        |

### 写真なしで残す

撮り忘れたとき (食べ始めてから、食べ終えてから気づいた) と、撮りにくい場 (カウンターの鮨、暗いバー、会食、撮影できない店) のため (2026-11-28、作り手の判断)。どちらも、その場かその日のうちに残す。昔の品をあとから入れる使い方は、今は考えない。ワイヤーフレーム: [`recording-flow.html`](recording-flow.html) の「H. 写真なしで残す」。

| 項目         | 決まり                                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入り口       | カメラの右下の「写真なし」と、＋ の長押し。長押しはカメラを開かずに残せる。撮りにくい場でカメラを向けると気まずいため                                    |
| 入れるもの   | 名前か種類のどちらか (両方でもよい)。名前を入れると、AI が名前から種類を推す                                                                             |
| 場所と時刻   | 撮ったときと同じく、今の位置と時刻から場所と食事が決まる。家に帰ってから残すときは、場所の欄で今日の食事の場所や検索から選び直し、時刻も今日の中で直せる |
| 食事に足す   | 食事の詳細の「品を足す」からも残せる。時刻と場所はその食事のものを使う                                                                                   |
| あとから写真 | 品の画面から写真を足せる                                                                                                                                 |
| 示し方       | 写真の代わりに種類を出す (見た目はデザインで決める)。気持ちの問いとランキングでも、名前 → 店 → 日付で示す                                                |

## 同じ食事のまとめ方

時刻と場所で自動にまとめる。店が分からなくても必ずまとまる。

- 直前の記録から数時間以内で、その食事の最初の記録から近ければ、同じ食事にする
- 起点を「直前の記録」にしない。商店街を少しずつ移動すると、1 日分が 1 食に連なってしまうため
- 距離の幅は GPS の精度に合わせて変える。屋内の誤差で 1 食が割れないようにするため

## 場所

- 場所の欄には、店・家・地域名のどれかが入る。買ってきたものには、買った店も入る。店に限らないので、欄の名前は「場所」にする
- 場所は食事ごとに持つ。同じ食事の 2 品目からは、その食事の場所が最初から入っている。品には、撮った位置と時刻を持つ
- 推定に自信があるときだけ店名を出す。ビルの中など候補が複数あるときは、地域名と候補数を出し、店を決め打ちしない
- 場所の欄は毎回出す。はしごで店が変わったら、ここで別の店を選ぶと、その品から新しい食事に分かれる
- 場所の欄をタップすると、近くの候補・検索・「家」・「店ではない」から選べる。候補は、近さ、行ったことがあるか、AI が付けた種類と店の業種が合うか、で並べる
- 家で撮った記録は、店の候補を出さずに「家」にする。買ってきたものは、場所をタップして買った店を選べる (下の「買ってきたもの」)
- ランキングに載るのは、店が決まった記録と、家の記録。店が決まっていない記録 (候補が複数) は載せない。間違った店がランキングに混ざらないようにするため。家の記録を入れるのは、家で食べたパンや家ごはんも比べられるようにし、好みの材料を偏らせないため (2026-11-28。[`taste.md`](taste.md) の前提)。マップには、店が決まっていない記録も地域のあたりに置く ([`history.md`](history.md) の「マップ」)。店が決まっていなくても、記録は残る

### 買ってきたもの

家で食べるパンやケーキ、家でいれるコーヒーの豆、家で開けるボトルなどは、場所に買った店を選べる。買った店も「場所」の欄にまとめ、別の欄は作らない (2026-11-28、作り手の判断)。種類を問わず同じにする。買って家で楽しむことが多い人も、外で食べることが多い人と同じように、どこの品かを残せるようにするため。ワイヤーフレーム: [`recording-flow.html`](recording-flow.html) の「G. 買ってきたものに、買った店を入れる」。

| 対象               | 決まり                                                                                                                                                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 見せ方             | 場所を選ぶシートを「ここで食べた」と「買ってきたもの」に分けて出す。買った店も場所の欄で選べることが、見てわかるようにするため                                                                                                                  |
| 候補               | 家で撮ったときは、「買ってきたもの」に、撮った場所の近くの店を、AI が付けた種類と店の業種が合うか、行ったことがあるか、で並べる。家の外で撮ったときは検索だけにする。遠くで買ったもの (旅先で買った品など) も検索で選ぶ                         |
| ヒント             | 家ではじめて残したときのトーストで、1 回だけ知らせる (言葉と出し方は [`onboarding.md`](onboarding.md) の「ヒント」)。家の記録は店の候補を出さずに残るので、知らせないと気づけないため                                                           |
| 欄の見え方         | 店の名前に「買ってきた」を添えて、買った店だと分かるように出す                                                                                                                                                                                  |
| 食事               | 食べたところ (家など) のまま。買った店はその品だけが持ち、同じ食事のほかの品 (家でいれたお茶など) は家のまま。買った店を選んでも、食事は分かれない                                                                                              |
| ランキング         | 家の記録と同じく載る。品は買った店の名前で示す ([`compare.md`](compare.md) の「品の示し方」)                                                                                                                                                    |
| マップ             | 買った店にもピンを立てる。また買いに行けるようにするため。食事は家のピンにも出る ([`history.md`](history.md) の「マップ」)                                                                                                                      |
| 実績               | 地域 (はじめての〇〇、N の都道府県) は撮った位置で数える。おみやげなどで、行っていない土地の実績は解除しない。店を数える実績 (軒数、同じ店) には、買った店も入れる。買って楽しむ人の店めぐりも数えるため ([`achievements.md`](achievements.md)) |
| 記録のタブのまとめ | 外食の回数には入れない (食べたのは家のため)。軒数には入れる ([`history.md`](history.md))                                                                                                                                                        |

## 例外と細かい決まり

| 対象                             | 決まり                                                                                                                                                                                                                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 取り消し                         | 保存したあと、トーストを出している間だけ「取り消す」を出す。解除した実績がいくつもあると、その分長く出る ([`achievements.md`](achievements.md))。取り消すと実績の解除も消える                                                                                                                           |
| 確認カードの ×                   | 撮って残した品では、直さずに閉じる (記録は残る)。写真から選んだときは、記録をやめて記録を始めた画面へ戻る。メモを書いていたときだけ確かめる。撮り直しは写真の上から行う                                                                                                                                 |
| 食事の分け直し                   | 確認カードの食事の表示 (「同じ食事 · 2 品目」) をタップし、「新しい食事にする / 前の食事に入れる」を選ぶ。家で朝と昼を食べたときなど、場所で分けられない場合に使う                                                                                                                                      |
| 店を後から選ぶ                   | 同じ食事で店が決まっていない前の品にも、同じ店を入れる。保存したあとは、記録のタブの食事の詳細で選ぶ ([`history.md`](history.md))                                                                                                                                                                       |
| あとから付いた種類と店           | そっと出すだけにする (2026-11-28、作り手の判断)。トーストに間に合えばトーストに出し、間に合わなければホームの最近の記録にそのまま出る。店が決まらなかった食事だけ、その行に「店を選ぶ」を出す。件数は出さず、ためない。通知は使わない                                                                   |
| 家                               | 「家」を選んだ場所を覚え、次からその近くでは家にする。家は複数覚えられる (実家など)。実績で帰省先の家も数えるため。覚えた家は設定から消せる ([`settings.md`](settings.md))                                                                                                                              |
| 位置がない写真                   | 受け取った写真、スクリーンショット、位置情報オフのとき。店は検索だけにし、食事のまとまりは時刻だけで決める                                                                                                                                                                                              |
| 電波がない                       | 地域名は端末の位置から出し、店の推定は電波が戻ってから行う。種類の判定も電波が戻ってから行う                                                                                                                                                                                                            |
| 判定できない                     | 料理か飲み物と分かって種類が分からないときは、種類を付けずに品として残る。確認カードや食事の詳細で手で選べる。選ばなくてもよい。料理か飲み物かも分からないときは、食事の写真になる (「品にする」で戻せる)                                                                                               |
| 写真から複数枚                   | 食事ごとにまとめた一覧で確認し、まとめて残す。品ごとに外せる。1 枚だけ選んだときは確認カードへ進む                                                                                                                                                                                                      |
| 記録済みの写真                   | 写真から選ぶとき、HINAMI で記録済みの写真は外して見せる。撮った写真を端末にも残すので、同じ品を二重に記録しないようにする                                                                                                                                                                               |
| 端末の写真を HINAMI から見に行く | しない。前回の記録のあとに撮った食の写真を候補に出す案、初回に過去の写真をまとめて取り込む案は採らない。はじめての人には、写真を勝手に見られているようで怖いため (作り手の判断。2026-11-27)。写真から選ぶのは、利用者が選んだときだけ                                                                   |
| まだ口にしていないもの           | 買ったボトルなどは、買ったときには記録しない。飲んだり食べたりするときに撮って記録する。買ったときに人に見せるのは、インスタなどほかの SNS の役割 (作り手の判断。2026-11-27)。「買ったもの」を食事と別のまとまりにして残す案は採らない。口にするときに、場所に買った店を選べる (上の「買ってきたもの」) |

## 気持ち

保存の流れには入れない。食べたあと、次にアプリを開いたときに、ホームのカードで気持ち (大好き / 好き / ふつう / 合わなかった) を 1 問だけ聞く。2 択は、ランキングの画面で自分から比べたいときだけ使う (詳細は [`compare.md`](compare.md))。

## 決めていないこと

- 通販で取り寄せた品の買った店。地図にない店 (通販だけの店) は、場所の検索では選べない
