# 記録の流れ (UX)

> **状態: 合意 (2026-11-26)**。ワイヤーフレームまで見て、この流れで進める。「案」はもうない。
>
> ワイヤーフレーム (画面遷移図): [`recording-flow.html`](recording-flow.html)。ブラウザで開く。

## 目的

ホームからいつもの記録までを、簡単で気軽にする。ここが重いと使われない。
PHASE 1 の関門は「作り手が 4 週間、覚えておきたい食をすべて記録できる」こと。

## 流れ

```
右下の [＋] (どの画面からでも)
 └─ カメラ ─ [シャッター] ──────┐
     └─ [写真から選ぶ] (左下) ──┤ (複数枚まとめて選べる)
                               ▼
                        確認カード ─ [残す] ─▶ もとの画面 (トーストで「残しました」)
```

- 画面の移動は、基本的にタブバーで行う
- 記録を残す入り口は、右下に浮かせた ＋ ボタン (2026-11-27 に、ホームのボタンから移した)。どの画面からでも記録を始められる。押すとすぐカメラが開き、写真から選ぶ入り口はカメラの左下に置く ([`navigation.md`](navigation.md))

- その場で撮っても、落ち着いてから写真から選んでも、同じ流れで記録できる
- 写真から選ぶ場合は、写真に残った位置と日時を使う
- アプリで撮った写真は、端末の写真アプリにも残す。ストーリーなどほかの SNS には、そこから上げる
- カメラと位置情報の許可は、はじめて ＋ を押したときに聞く。はじめての確認カードでだけ、ヒントを 1 つ出す ([`onboarding.md`](onboarding.md))
- 保存したら、記録を始めた画面に戻り、トーストで「残しました」を出す。解除した実績と、はじめての種類も同じトーストに出す。タップは増やさない (詳細は [`achievements.md`](achievements.md))

## 確認カード

```
写真
[ラーメン ▾]            AI がその場で種類を付ける。違えばタップで直す
場所 麺屋 ひかり ▾        推定に自信があるとき: 店名
    道玄坂・候補 3 件 ▾  自信がないとき: 地域名 (店を決め打ちしない)
シェア 友だち ▾          友だちがいるときだけ出す。食事ごと
メモ (任意)
               [残す]
```

AI や推定で入るもの (種類、場所) は、すべて同じ扱いにする。確認カードに出し、違えばその場で直せる。直さなくても残せる。それとは別に、利用者に分類を登録させることはしない。

| 項目       | 決まり                                                                                                                                                                                                                                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 必須の入力 | なし。写真だけで記録になる                                                                                                                                                                                                                                                                                                             |
| 種類       | 画像判定の AI がその場で付ける (1 秒未満)。1 枚に複数写っていれば複数付く (ラーメンとビールなど)。間違っていたらその場で手で直す。種類は運営が持つ 3 段の一覧 (大分類 → 種類 → 細かい種類) から付き、確認カードには真ん中の「種類」を出す ([`kinds.md`](kinds.md))。食・飲はその上の大カテゴリとして裏で決まり、利用者には登録させない |
| 場所       | 下の「場所」を参照                                                                                                                                                                                                                                                                                                                     |
| メモ       | 任意。品名は分からないことが多いため、必須にしない。AI が写真から銘柄や品名を読めたときは、メモの候補として出し、タップで入れられる (詳細は [`history.md`](history.md))                                                                                                                                                                |
| シェア     | 友だちがいるときだけ出す。食事単位で、どの品のカードで変えても同じ食事の品すべてに効く。既定は「友だち」で、シェアしたくない食事だけ「自分だけ」にする (詳細は [`connect.md`](connect.md))                                                                                                                                             |
| 電波がない | 保存を先に済ませ、電波が戻ったら判定する                                                                                                                                                                                                                                                                                               |

## 同じ食事のまとめ方

時刻と場所で自動にまとめる。店が分からなくても必ずまとまる。

- 直前の記録から数時間以内で、その食事の最初の記録から近ければ、同じ食事にする
- 起点を「直前の記録」にしない。商店街を少しずつ移動すると、1 日分が 1 食に連なってしまうため
- 距離の幅は GPS の精度に合わせて変える。屋内の誤差で 1 食が割れないようにするため

## 場所

- 場所の欄には、店・家・地域名のどれかが入る。店に限らないので、欄の名前は「場所」にする
- 場所は食事ごとに持つ。同じ食事の 2 品目からは、その食事の場所が最初から入っている。品には、撮った位置と時刻を持つ
- 推定に自信があるときだけ店名を出す。ビルの中など候補が複数あるときは、地域名と候補数を出し、店を決め打ちしない
- 場所の欄は毎回出す。はしごで店が変わったら、ここで別の店を選ぶと、その品から新しい食事に分かれる
- 場所の欄をタップすると、近くの候補・検索・「家」・「店ではない」から選べる。候補は、近さ、行ったことがあるか、AI が付けた種類と店の業種が合うか、で並べる
- 家で撮った記録は、店の候補を出さずに「家」にする
- 店のランキングに載るのは、店が決まった記録だけ。間違った店がランキングに混ざらないようにするため。マップには、店が決まっていない記録も地域のあたりに置く ([`history.md`](history.md) の「マップ」)。店が決まっていなくても、記録は残る

## 参考にした事例

| 事例                        | 型                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------- |
| Swarm                       | 位置の履歴や写真から、あとでチェックインする候補を出す                                    |
| Google マップのタイムライン | 自動で記録した訪問先を、あとから候補の一覧で選び直す                                      |
| Untappd                     | 店は任意。近さと自分が行った回数で候補が並ぶ                                              |
| Apple の写真アプリ          | 写真を店名ではなく地域名でまとめる                                                        |
| Foursquare                  | 店が縦に積み重なった密集地は判別が難しい、と自ら書いている (ビルの中で決め打ちしない根拠) |

## 例外と細かい決まり

| 対象                             | 決まり                                                                                                                                                                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 取り消し                         | 保存したあと、数秒だけ「取り消す」を出す。取り消すと実績の解除も消える                                                                                                                                                                 |
| 確認カードの ×                   | 記録をやめて、記録を始めた画面へ戻る。メモを書いていたときだけ確かめる。撮り直しは写真の上から行う                                                                                                                                     |
| 食事の分け直し                   | 確認カードの食事の表示 (「同じ食事 · 2 品目」) をタップし、「新しい食事にする / 前の食事に入れる」を選ぶ。家で朝と昼を食べたときなど、場所で分けられない場合に使う                                                                     |
| 店を後から選ぶ                   | 同じ食事で店が決まっていない前の品にも、同じ店を入れる。保存したあとは、記録のタブの食事の詳細で選ぶ ([`history.md`](history.md))                                                                                                      |
| 家                               | 「家」を選んだ場所を覚え、次からその近くでは家にする。家は複数覚えられる (実家など)。実績で帰省先の家も数えるため。覚えた家は設定から消せる ([`settings.md`](settings.md))                                                             |
| 位置がない写真                   | 受け取った写真、スクリーンショット、位置情報オフのとき。店は検索だけにし、食事のまとまりは時刻だけで決める                                                                                                                             |
| 電波がない                       | 地域名は端末の位置から出し、店の推定は電波が戻ってから行う。種類の判定も電波が戻ってから行う                                                                                                                                           |
| 判定できない                     | 種類を付けずに出し、手で選ぶ。選ばなくても残せる                                                                                                                                                                                       |
| 写真から複数枚                   | 食事ごとにまとめた一覧で確認し、まとめて残す。品ごとに外せる。1 枚だけ選んだときは確認カードへ進む                                                                                                                                     |
| 記録済みの写真                   | 写真から選ぶとき、HINAMI で記録済みの写真は外して見せる。撮った写真を端末にも残すので、同じ品を二重に記録しないようにする                                                                                                              |
| 端末の写真を HINAMI から見に行く | しない。前回の記録のあとに撮った食の写真を候補に出す案、初回に過去の写真をまとめて取り込む案は採らない。はじめての人には、写真を勝手に見られているようで怖いため (作り手の判断。2026-11-27)。写真から選ぶのは、利用者が選んだときだけ  |
| まだ口にしていないもの           | 買ったボトルなどは、買ったときには記録しない。飲んだり食べたりするときに撮って記録する。買ったときに人に見せるのは、インスタなどほかの SNS の役割 (作り手の判断。2026-11-27)。「買ったもの」を食事と別のまとまりにして残す案は採らない |
