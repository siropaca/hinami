# 比べる (自分のランキング)

> **状態: 合意 (2026-11-26)**。聞くタイミングと、順位の決め方まで決めた。2026-11-28 に、答えにくい組み合わせのために「比べられない」を置いた。同じ日に、聞く品を食べてから日が浅い品に絞った。

ワイヤーフレーム: [`recording-flow.html`](recording-flow.html) の「F. 比べる (食べたあと)」。

## 目的

点数はつけずに、「どちらが好き?」の 2 択に答えるだけで、種類ごとの自分の好きな順が育つ ([`../concept.md`](../concept.md))。記録の手軽さは崩さない。

## いつ聞くか

保存した直後には聞かない。食べたあと、次にアプリを開いたときに、ホームのカードで 1 問だけ聞く。

- 料理はたいてい食べる前に撮るので、保存した直後はまだ味を知らない
- 保存の流れに画面を足さないので、記録は最短 2 タップ (＋ → シャッター) のまま
- 写真から選んで残した記録はもう食べ終えているので、保存後のトーストが消えたらすぐに出してよい

```
ホーム (食べたあと、次に開いたとき)
┌─────────────────────────────┐
│ どちらが好き?               ラーメン │
│ [今回: 特製醤油 · 麺屋 ひかり] [前の: 中華そば 青葉 · 11/12] │
└─────────────────────────────┘
        ↓ 答える
┌─────────────────────────────┐
│ 3〜4 位まで絞れました     続けて比べる │
└─────────────────────────────┘
```

| 項目             | 決まり                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 出す場所         | ホームのカード。別の画面にしない。アプリを開いたときに出す問いなので、プッシュ通知は使わない                                                                                                                                                                                                                                                                                                                                         |
| 数               | アプリを開いたときに 1 問だけ                                                                                                                                                                                                                                                                                                                                                                                                        |
| 何を聞くか       | 食べてから日が浅い品 (今の案: 7 日以内) を、新しい順に聞く。同じ食事の品どうしは聞かない。1 つの食事の同じ種類の品は、ホームでは 1 品だけ聞く (コースで同じ種類が並んでも、問いが続かないように)。同じ種類に比べる相手がいる品だけが対象。それより古い品はホームでは聞かず、幅のまま残る (ランキングの画面からはいつでも比べられる)。相手はもともと過去の品なので、せめて聞かれる側の品は、味を覚えているうちに聞くため (2026-11-28) |
| 保存後のトースト | 「残しました」のトースト (実績と、はじめての種類を含む) とは同時に出さない。それが消えてから、ホームのカードで出す                                                                                                                                                                                                                                                                                                                   |
| 品の示し方       | 写真と、「名前 → 店 → 日付」の順。名前がないときは店と日付。家で食べた買ってきた品は、買った店で示す ([`recording.md`](recording.md) の「買ってきたもの」)。写真のない品は、写真の代わりに種類を出す。同じ店の 2 杯や、家の品どうしも見分けられるようにする (2026-11-28。[`../research/2026-11-28/README.md`](../research/2026-11-28/README.md) の施策 2)                                                                            |
| 答え方           | 2 つのどちらかをタップする。触らなければ流れる。比べにくいときは「比べられない」を押す                                                                                                                                                                                                                                                                                                                                               |
| 比べられない     | カードに小さく「比べられない」を置く。種類が同じでも比べにくい組み合わせ (赤ワインと白、立ち食い寿司とおまかせ、手作りの品と店の品など) があるため。押したら、その組み合わせは二度と聞かず、その場で別の相手に替える。答えた数には数えない。ほかに相手がいなければカードを閉じ、品は幅のまま残る。ランキングの画面から比べるときも同じ (2026-11-28、作り手の判断)                                                                    |
| 続けて比べる     | 答えたあと、カードに小さく出す。押さなくてよい。押せばその場で順位を決めきれる                                                                                                                                                                                                                                                                                                                                                       |
| ためない         | 「未回答 N 件」のようにためない。次に開いたときは、そのとき聞ける品のうち、いちばん新しい品から聞き直す                                                                                                                                                                                                                                                                                                                              |
| 相手             | 自分の記録だけ。最初の数週は同じ種類の相手が少なく、問いはあまり出ない。比べるのは、3 段の真ん中の「種類」(ラーメン、日本酒など) どうし。一覧にないものが入る「その他」は比べない ([`kinds.md`](kinds.md))。相手は、AI が付けた細かい種類 (赤、白など) が同じ品を先に選ぶ (下の「順位の決め方」)                                                                                                                                     |
| いつでも比べる   | ランキングの画面からは、いつでも比べられる                                                                                                                                                                                                                                                                                                                                                                                           |
| 入口             | 記録のタブを種類で絞ったときだけ、一覧の上にその種類のランキングの入口を出す。比べる相手がいないうちは出さない                                                                                                                                                                                                                                                                                                                       |

必ず答えさせる Beli と比べて、答えが集まる数は少なく、ランキングが育つのも遅くなる。記録を気軽にすることを優先する前提に合うので、それを受け入れる。

## 順位の決め方

比べた答えを使って、新しい品を今のランキングの中に二分で挿し込む (Beli と同じ型)。1 問答えるたびに、入りうる順位の幅が半分になる。

```
いまのラーメン 7 杯 (好きな順)
1 A   2 B   3 C   4 D   5 E   6 F   7 G

新しい H を入れる
1 問目: H と D (真ん中)  → H が好き → H は 1〜4 位のどこか
2 問目: H と B           → B が好き → H は 3〜4 位
3 問目: H と C           → H が好き → H は 3 位に決まる
```

- 順位が決まるまでの問いの数は、同じ種類の品の数で決まる。8 品なら 3 問、16 品なら 4 問、32 品なら 5 問
- 順位は答えた範囲で決まる。品どうしの差を点数で持たない
- 相手は、入りうる幅の真ん中の品にする。ただし、真ん中の品と細かい種類 (赤、白など) が違うときや、「比べられない」とした組み合わせのときは、幅の中で真ん中に近い、細かい種類が同じ品にする。細かい種類が分からない品は、種類が同じなら相手にする。幅がちょうど半分にならない問いも出るが、答えやすさを優先する (2026-11-28)
- ランキングの画面では、順位が決まった品は番号で、まだ決まっていない品は「3〜4 位」のように幅で見せる
- ランキングの画面では手で並べ替えられる。好みが変わったときや、答えを間違えたときのため

### 採らない方式

| 方式                                               | 採らない理由                                                                                               |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 保存した直後に 1 問 (前の案)                       | 食べる前に聞くことになる。保存のたびに画面が 1 枚増え、記録の手数が増える                                  |
| 1 回の食事で 1 問、答えなければ差し替える (前の案) | 新しい品が「1〜4 位のどこか」のまま止まりやすく、ランキングが暫定ばかりになる                              |
| 勝ち負けから見えない点数を推定する (Elo など)      | 答えるたびにほかの品の順位まで揺れる。なぜその順位なのかを説明しにくく、自分の好きな順を作る用途に合わない |
| ランキングの画面でしか聞かない                     | 答えが集まらない                                                                                           |
| 順位の幅がいちばん広い品から聞く (前の案)          | 数週間前の品が出て、味を覚えていないことがある                                                             |

## 入れないもの

| もの                           | 理由                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 店に付ける「また行きたい」の印 | 同じ店に何度も行くことはあまりない (作り手の声。[`taste.md`](taste.md))。品の好きな順と、好みのことばで足りる |

## PHASE 1 で確かめること

PHASE 1 の合否は作り手の手応えで決める ([`../concept.md`](../concept.md))。ここに挙げる数字は、アプリが自動で残せるものだけにし、見返しの材料にする。

- 出した問いの数と、答えた率。「次に開いたとき」に聞くので、記録するときしか開かない人には問いが遅れる。その遅れが答えた率を下げていないかを見る
- 食べてから答えるまでの日数。「7 日以内」の線が合っているかを、答えた率と合わせて見直す
- 「比べられない」を押した率と、押された組み合わせ。細かい種類で相手を選ぶ決まりが足りているかを見る

## 参考にした事例

| 事例 | 型                                                                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Beli | 店に行ったあとに記録し、「好き / 普通 / 好きでない」を選んでから 2 択を数問続けて順位を決める。2 択が続くのは面倒という声もある。答えにくいときの「Too tough」と、とばす、1 つ前の問いに戻る、がある。それでも、分類 (料理の系統や価格帯) が違う店どうしは比べられないという声が残る |

Beli の答えにくいときの扱いは、第三者の記事による (アプリでは確かめていない): [Pratt IXD のデザイン批評](https://ixd.prattsi.org/2022/02/design-critique-beli-ios-app/)、[Spoon University](https://spoonuniversity.com/school/emory/rate-save-and-recommend-restaurants-on-app-beli/)、[HackerNoon](https://hackernoon.com/belis-binary-search-rating-system-explained)

## 決めていないこと

- コース全体どうしを比べる受け皿 (おまかせの鮨の店どうしなど)。今は品どうしだけを比べる ([`recording.md`](recording.md) の「品と写真」)
- 種類の一覧の中身 (どの種類を入れるか)。粒度は「ラーメン」「日本酒」くらいに決めた ([`kinds.md`](kinds.md))
