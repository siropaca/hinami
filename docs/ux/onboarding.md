# 最初のチュートリアルとアカウント (UX)

> **状態: 決めた (2026-11-27)**。作り手から任されて決めた。気になる点があれば直す。
>
> ワイヤーフレーム: [`onboarding-flow.html`](onboarding-flow.html)。ブラウザで開く。

## 目的

はじめて開いてから最初の記録までを短くする。アカウントと許可は、チュートリアルと最初の記録の中で、使う場面ごとに済ませる。

## 流れ

```
はじめて開く
 → ようこそ           Google で続ける (アカウントができる)
 → 通知のお願い       [受け取る] → OS の許可 / [あとで]
 → ホーム (0 件)      右下の ＋ へ案内する
 → はじめての ＋      カメラと位置情報の許可
 → はじめての確認カード  1 回だけヒントを出す
```

## 決まり

| 項目                 | 決まり                                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ようこそ             | 1 枚だけ。何ができるかを 3 行で見せ、その下に「Google で続ける」を置く                                                                                                                                 |
| アカウント           | 最初に作る。まずは Google だけで、1 タップで作る。メールアドレスとパスワードは使わない                                                                                                                 |
| 同意                 | 続けるボタンの下に「続けると、利用規約とプライバシーポリシーに同意したことになります」と書き、それぞれへのリンクを置く                                                                                 |
| 名前                 | ここでは聞かない。友だちの機能をはじめて使うとき (QR コードを見せる・読み取るとき) に決める                                                                                                            |
| 通知                 | 先に HINAMI の画面で、何を知らせるかを見せる。「受け取る」を押したときだけ OS の許可を出す。「あとで」なら OS の許可は出さず、設定からあとで受け取れる                                                 |
| 運営からのお知らせ   | 宣伝を含むなら、通知のお願いの画面に、受け取るかどうかの同意を別に置く (既定はオフ)。App Store の審査ガイドライン 4.5.4 のため。中身は未決                                                             |
| カメラ・位置情報     | はじめて ＋ を押したときに聞く。位置情報は、撮った場所を記録するのと、マップの現在地に使う                                                                                                             |
| 写真 (端末に残す)    | はじめて「残す」を押したときに聞く                                                                                                                                                                     |
| 写真 (写真から選ぶ)  | はじめて「写真から選ぶ」を押したときに聞く                                                                                                                                                             |
| 許可されなかったとき | カメラ: 写真から選ぶだけで記録できる。位置情報: 場所は検索で入れる ([`recording.md`](recording.md) の「位置がない写真」と同じ)。写真を残す: 撮った写真を端末に残さない。どれもあとから設定で変えられる |
| ヒント               | はじめての確認カードで 1 回だけ、「種類と場所は自動で入ります。違うときだけ直してください」と出す                                                                                                      |
| アカウントの削除     | 設定 → アカウント → アカウントを削除。記録・写真・友だち・メッセージをすべて消す。消す前に、消えるものを見せて確かめる (App Store の審査ガイドライン 5.1.1)                                            |
| ログアウト           | 設定 → アカウント。記録はサーバーに残り、同じアカウントで入れば戻る                                                                                                                                    |

## 理由

- 記録帳は、積み重ねた記録そのものが財産。アカウントがないと、機種変更や紛失で記録が消える。はじめからアカウントがあれば、記録はいつもサーバーに置け、友だちの機能を使い始めるときに記録を移し替える必要もない
- まずは Google のログインだけにする (作り手の判断)。App Store に出すときは、Google のログインだけでは審査ガイドライン 4.8 に触れるので、Sign in with Apple など同等のログインを足す ([`../open-questions.md`](../open-questions.md))
- チュートリアルは短くする。説明の画面を何枚も見せるより、早く最初の記録まで連れていく。使い方は、確認カードのヒント 1 つで足りる
- 許可は使う場面で聞く。何に使うかがその場で分かり、許可されやすい (Apple のガイドラインも同じ考え)。通知だけは、運営からのお知らせもあるのでチュートリアルで聞く (作り手の判断)
- 通知は、OS の許可を 1 回しか出せない。先に HINAMI の画面で説明し、「受け取る」を選んだ人にだけ OS の許可を出す

## 採らなかった案

| 案                                       | 採らない理由                                                         |
| ---------------------------------------- | -------------------------------------------------------------------- |
| 友だちの機能を使うときにアカウントを作る | 作る前の記録が機種変更で消える。サーバーへ移し替える仕組みが別に要る |
| 説明の画面を何枚も見せる                 | 最初の記録が遠くなる                                                 |
| 許可をチュートリアルでまとめて聞く       | 何に使うかが分かりにくく、断られやすい                               |

## 決めていないこと

- 運営からのお知らせの中身 (宣伝を含むか)
- 利用規約とプライバシーポリシーの中身
- ようこそで見せる 3 行の言葉
