# 実績 (続けたくなる仕組み)

> **状態: 合意 (2026-11-26)**。仕組みの形と、最初に入れる実績の一覧まで決めた。2026-11-27〜28 に、地域を都道府県の単位にし、解除の出し方 (入れ替えと動き) と、名前と条件の言葉の方針を決めた。実績の中身と名前は今の案で、使いながら調整する。調整するときの拠り所は「方針」と、「名前と条件の言葉」の方針。

## 目的

記録するたびに、HINAMI 自身が小さな見返りを返す。作り手 1 人で使う PHASE 1 の 4 週間でも効くこと。

## 背景 (作り手の声)

- 続いているのはインスタのストーリーと Locket。気軽に上げられ、上げたあと知り合いからスタンプやいいね、ときどき「どこ?」「おいしそう」の DM が届いて話が広がる。他の人の投稿も見られる
- そこに上げている食: いいレストラン、いいお酒を買ったとき、凝った手料理、おいしい・美しい料理、おしゃれなカフェ
- それらの SNS への不満: 写真を後から見返しづらい、食べた場所が分からない、分類できない
- 「残していくたびに、いろんな実績が解除される仕組みがあると続きそう」。使ったことはなく、どんな実績が効くかは使ってみないと分からない

## 方針

実績の中身 (どの実績を置くか、段の数、名前) は、使いながら調整する。調整するときも、運営があとから足すときも、次の方針に沿う。

| 方針                                                                                                                   | 理由                                                                                       |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 記録が積み重なった節目として返す。記録させるための仕掛けにしない                                                       | すべて記録することは求めない。件数を稼がせると記録が義務になり、記録そのものも濁る         |
| 義務感を生まない。連続日数、総件数、前もって知らせる期間限定は入れない                                                 | 義務感は逆効果 (前提)。詳しくは下の「入れないもの」                                        |
| 酒で、飲む量を伸ばす仕組みを作らない (一晩の杯数・軒数など)。酒の回数の段をどうするかは未決 (下の「決めていないこと」) | App Store の審査ガイドライン 1.4.3。飲む量を称えるバッジは、ほかのアプリで実際に批判された |
| 同じ食事の中では、同じ種類・同じ店を 1 回と数える                                                                      | 一晩の杯数や品数で実績が進まないようにする                                                 |
| 最初の段は低く刻む (2・3・5 回)                                                                                        | PHASE 1 の記録は 4 週間で十数件から二十数件。高い段だけでは 3〜4 週目に何も起きない        |
| 一人で使っても効く                                                                                                     | つながりは上乗せ ([`../concept.md`](../concept.md))                                        |
| 一度解除したら、記録を直しても取り消さない。「取り消す」で記録そのものがなくなったときだけ消す                         | 一度渡したものを取り上げない                                                               |
| 名前で笑わせ、条件は淡々と書く                                                                                         | 下の「名前と条件の言葉」                                                                   |
| 知らせは煩わしくしない。タップを増やさず、比べると同時に出さない。いくつもあれば 1 つずつ入れ替え、動きで嬉しさを出す  | ただの通知に見えると煩わしい。詳しくは下の「見せ方」                                       |
| 実績のタブでは、すべての実績を同じ形で見せ、空いた枠が見えるようにする                                                 | 「埋めていきたい」「解除していきたい」と思えるように (作り手の判断)                        |

## 何がいつ返るか

| いつ       | 返るもの                                              | どこで                                                                                           |
| ---------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 記録の直後 | 実績の解除、はじめての種類                            | HINAMI                                                                                           |
| 記録の直後 | 人からの反応                                          | HINAMI の中のつながっている人と、ストーリーなど今の SNS (撮った写真は端末に残り、そこから上げる) |
| あとから   | 見返す、場所が分かる、分類できる (記録のタブ・比べる) | HINAMI                                                                                           |

HINAMI の中のつながりは最初の版から入れる。ただし一人で使っても成り立つことが前提 ([`../concept.md`](../concept.md))。

## 実績の形

実績は、記録が積み重なった節目として作る。区分は 2 つで、「シークレット」「期間」はどちらにも付けられる印にする。「シークレット」は、はじめ「隠し」「ひみつ」と呼んでいた (作り手の判断で改めた)。

| 区分              | 何で解除されるか                                                                 | 例                                                      |
| ----------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 初めて (広がり)   | 新しい土地や場面に、初めて出会う                                                 | はじめての京都府 (2 つめの都道府県)、はじめての家ごはん |
| 積み重ね (深まり) | 同じものが重なる。最初の段は 2・3・5 回と低く刻む                                | 同じ店に 3 回、ラーメン 3 回、5 軒                      |
| 印: シークレット  | 条件を伏せ、解除されて初めて分かる。一覧には「シークレット あと N 個」とだけ出す | 0 時を過ぎたシメ                                        |
| 印: 期間          | 運営が足す季節もの。前もって知らせず、あとで気づく                               | ある年の冬だけの鍋                                      |

- 種類を使う実績は、AI が付けた種類 (ラーメン、日本酒など) で数える。食・飲は種類の上の大カテゴリとして裏で持つ
- 最初の段を低く刻むのは、PHASE 1 の記録は 4 週間で十数件から二十数件と見ており、高い段だけでは 3〜4 週目に何も起きなくなるため
- 店を使う実績は、店が決まった記録だけを数える
- 同じ食事 (時刻と場所でまとまった記録) の中では、同じ種類・同じ店は 1 回と数える。一晩に日本酒を 5 杯記録しても「日本酒 5 回」にはしない

## はじめての種類

はじめての種類 (例: 日本酒) は、実績にせず、保存したときのトーストに 1 行で知らせる。行の頭は「実績」にする。

| トーストの行 (言葉は仮) | 実績のタブでは                                                      |
| ----------------------- | ------------------------------------------------------------------- |
| 実績 パン、お目見え     | その種類の実績が現れる (まだ解除していない。輪で次の段までを見せる) |

- 実績にしないのは、出る回数が多すぎるため。仮の 1 か月 (20 件) で試算すると、記録 1 件につき実績が 2 つずつ出て、その半分が、はじめての種類と、はじめての区市町村だった
- アプリの「はじめて」は初めて記録しただけで、初めて食べたわけではない。よくある種類ほど「おっ」とならない
- 行の頭を「実績」にするのは、新しい言葉を作らず、見に行く場所がすぐ分かるようにするため。はじめは「図鑑への追加」と呼んでいたが、実績のタブから種類の一覧をなくしたので改めた
- 「はじめて 日本酒」とだけ出す案は採らない。実績のタブに「はじめて」の一覧は置かず、見に行く先がないため

### 地域は都道府県の単位にする

地域の「はじめて」は、都道府県の単位だけにする (2026-11-27、作り手の判断)。はじめての都道府県は、実績の「はじめての〇〇」で返る (下の「最初に入れる実績」)。区市町村の「はじめて」は知らせない。

- はじめは、区市町村の「はじめて」(家は除く) も、トーストの「マップ 渋谷区 がはじめて」で知らせていた。マップを記録のタブに移したときに、実績に載せるかを話し、都道府県の単位にした
- 区市町村ごとに 1 つずつ実績にする案と、都道府県の実績の中で区市町村の枠を埋める案は採らなかった
- 区市町村をやめると、1 週目に返るものが減る (以前は、そのために地域を残していた)。返るものが足りるかは、PHASE 1 で確かめる

## 最初に入れる実績

今の案。使いながら、上の「方針」に沿って調整する。

「〇〇」が入るものは、種類ごと・店ごと・都道府県ごとに自動で作る。

| 区分         | 実績                      | 数え方                                                                              | 段階                     |
| ------------ | ------------------------- | ----------------------------------------------------------------------------------- | ------------------------ |
| 初めて       | はじめての〇〇 (都道府県) | 2 つめの都道府県から出す。最初の 1 つは基準の土地なので出さない。帰省先の家も含める | —                        |
| 初めて       | はじめての家ごはん        | 家で撮った食べ物。惣菜や出前も入るので「手料理」ではなく「家ごはん」と呼ぶ          | —                        |
| 積み重ね     | 〇〇 (種類) N 回          | 同じ食事の中では 1 回                                                               | 2・3・5・10・25・50・100 |
| 積み重ね     | 〇〇 (店) に N 回         | 店が決まった記録。同じ食事の中では 1 回                                             | 2・3・5・10・25・50・100 |
| 積み重ね     | N の都道府県              | 家も含める                                                                          | 2・5・10・20・47         |
| 積み重ね     | N 種類                    | 記録した種類の数                                                                    | 種類の一覧が決まってから |
| 積み重ね     | N 軒                      | 店が決まった、別々の店の数。一晩で回った軒数とは別物                                | 5・10・20・50・100       |
| シークレット | 朝の一皿                  | 朝 5〜10 時の食べ物                                                                 | —                        |
| シークレット | 0 時を過ぎたシメ          | 0〜5 時の食べ物                                                                     | —                        |
| シークレット | 大晦日のそば              | 12 月 31 日のそば。1 日は朝 5 時で区切るので、1 月 1 日の 0 時台も入る              | —                        |

- 同じ店の回数は、リピートが少ないので解除されにくい。それでよい。めったに起きないからこそ、解除したときに価値がある難しい実績にする (2026-11-28、作り手の判断)
- 時刻を使う実績は、写真の撮影時刻だけで判定する。撮影時刻のない画像 (スクリーンショット、保存した画像) は対象にしない
- 大晦日のそばは毎年の日付の条件で、期間限定ではない。印は「シークレット」だけにし、過去の記録へのさかのぼりも効く
- 25・50・100 の高い段は、使い始めて数か月で低い段を出し尽くしたときのために、最初から入れておく。その先は、運営があとから足す実績と年間ふりかえりが担う。実績だけで続けさせようとしない

### 試算

仮の 1 か月 (記録 20 件、東京、店 7 軒のうち 3 軒に再訪) で数えた。記録は想定で作ったもので、実際の数は使ってみないと分からない。

| 週     | 実績 | はじめての種類・区市町村 |
| ------ | ---- | ------------------------ |
| 1 週目 | 2    | 7                        |
| 2 週目 | 4    | 4                        |
| 3 週目 | 7    | 3                        |
| 4 週目 | 3    | 5                        |

この試算は、区市町村の「はじめて」も知らせていたときのもの。そのときは、どの記録でも何かが返り、1 週目は実績が少ないぶん「はじめて」が多かった。地域を都道府県の単位にしたので、右の列のうち区市町村の分はもう返らない (内訳は残していない)。返るものが足りるかは、PHASE 1 で確かめる。

## 名前と条件の言葉

方針を決めた (2026-11-28、作り手の判断)。ゲームやアプリの実績を調べ、別の目でレビューして決めた。名前そのものは今の案で、使いながら直す。直すときも足すときも、次の方針に沿う。

### 方針

- **名前で笑わせ、条件は淡々と書く**。名前は遊び、条件は事実だけにする。条件は文として、です・ます調でやわらかく書き、体言止めにしない (アプリの中の言葉の決まり。[`../../AGENTS.md`](../../AGENTS.md))。名前だけでは何をしたか分からないので、条件で補う。条件が淡々としているほど、名前のおかしさが立つ (ゲームの実績と同じ組み合わせ)

```
│ 残しました · 麺屋 ひかり        取り消す │
│ 実績を解除   いつもの、で通じる          │  ← 名前
│              麺屋 ひかり で 5 回記録しました │  ← 条件
```

- **大人のウィットにする**。対象は 30〜40 代で、世界観は「日々の帳面」([`../design/direction.md`](../design/direction.md))
  - 使う型: 控えめな言い方 (あつ森の「控えめに言って有識者」のような)、ことわざ・慣用句のもじり、段が上がるほど育つ言い方、段をまたいで対になる掛け
  - 使わない: 幼稚・ポップな言葉、ネットの定型 (「ほぼ〇〇」)、広告の定型 (「〇〇、卒業」)、すぐ古びる流行語、知っている人にしか通じない掛け (特定の地名など)
- **段は順に強くする**。下の段は控えめに、中ほどは少し誇張し、いちばん上は大げさに言い切る。前の段より弱く見える言葉は置かない。足したり直したりしたら、段の並びで続けて読んで確かめる
- **自動で作る実績は、段ごとの言葉を使い回す**。種類ごと・店ごと・都道府県ごとの実績は、段ごとの言葉を一度だけ書き、〇〇 に名前を入れる (あつ森の称号や Untappd と同じやり方)。種類や店が増えても、名前を書き足さなくてよい。どの名前が入っても自然な日本語になる言葉を選び、いくつか入れて読んで確かめる (ラーメン、寿司、コーヒー、ケーキ、麺屋 ひかり、鮨 はやし など)
- **酒の冗談にしない**。飲む量や回数を称えない。酔い、二日酔い、ツケのように、飲む場面を連想させる冗談も避ける (App Store の審査ガイドライン 1.4.3。Untappd や Foursquare の飲酒のバッジは、実際に批判された)
- **本人をからかわない**。自分の大事な記録に付く名前なので、きつく揶揄しない。夜更けの一品のように後ろめたさのあるものも、咎めずに言う。死や腐敗のような、きつい言葉は使わない
- **条件は事実に合わせる**。アプリの「はじめて」は初めて記録しただけで、初めて食べたとは限らないので、「はじめて記録しました」と書く。回数と軒数は数字で書く
- **足す・直すときは、別の目でレビューする**。対象ユーザー (食と飲みにこだわる 40 歳前後。好みの違う人を入れる) とコピーライターの 2 つの立場で読み、方針に反していないか、段が順に強くなっているかを見る
- 記号 (「、」「:」) の見え方は、デザインのフェーズで確かめる

## 見せ方

ワイヤーフレーム: [`recording-flow.html`](recording-flow.html) の「A. その場で撮る」の保存後。

```
保存したときのトースト (実績の行は 1 つずつ入れ替わる)
┌──────────────────────────┐
│ 残しました · 麺屋 ひかり   取り消す │
│ 実績を解除  のれんをくぐる癖       │  ← 実績の解除。2 秒ほどで次へ
│             5 軒で記録しました     │
└──────────────────────────┘
                 ↓
│ 実績        ラーメン、お目見え     │  ← はじめての種類
```

- 解除の知らせと、はじめての種類は、保存したときの「残しました」のトーストに一緒に出す。タップは増やさない
- いくつも出たときは、数の上限を決めず、1 つずつ 2 秒ほどで入れ替えて出す。ゲームの実績の解除と同じ形 (2026-11-28、作り手の判断)。「残しました」と「取り消す」は出したままにし、実績の行だけを入れ替える。トーストは、すべてを出し終えるまで出しておき、その間は取り消せる
- ただの通知に見えると煩わしいので、動きで解除の嬉しさを出す (作り手の判断)。動きの中身はデザインのフェーズで決める
- 比べる 1 問は、このトーストと同時に出さない。トーストが消えてから、ホームのカードで出す ([`compare.md`](compare.md))
- 「取り消す」を押したら、解除の知らせも一緒に消える
- 解除した実績と進み具合は、実績のタブで見る。中身も「実績」と呼び、「スタンプ」とは呼ばない (作り手の判断。[`navigation.md`](navigation.md))。ホームに「あと 2 回」のような表示は出さない
- 実績のタブは、ゲームの実績やスタンプラリーのように、すべての実績を同じ形で見せる (作り手の判断。「埋めていきたい」「解除していきたい」と思えるように)。解除した実績は塗りつぶし、進行中のものは周りの輪で進み具合、シークレットは「?」。段階のある実績は 1 つにまとめ、タップするとボトムシートで段ごとの枠が並ぶ (作り手の判断)。都道府県は 47 の枠を埋めていく。画面は一旦この形で、実績の種類 (どの実績を置くか、並べ方の分け方) はあとで詰める ([`achievements-flow.html`](achievements-flow.html))

## 入れないもの

| もの                                         | 理由                                                                                                                 |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 連続日数                                     | 義務感は逆効果 (前提)                                                                                                |
| 総件数 (「50 件記録」)                       | 件数を目標にすると、記録が義務になる。すべて記録することは求めない                                                   |
| 杯数・軒数を伸ばすもの (「一晩で 3 軒」)     | 過度の飲酒を勧めるアプリは App Store の審査ガイドライン 1.4.3 で禁止されている。量ではなく、種類や土地の広がりで作る |
| 前もって知らせる期間限定                     | 取り逃したくない気持ちが義務になる。STEP 2 の協賛ラリーは、告知する別の仕組みとして分ける                            |
| はじめての種類 (実績として)                  | 出る回数が多すぎる。実績にせず、トーストの 1 行で知らせる (上の「はじめての種類」)                                   |
| 区市町村の「はじめて」                       | 地域は都道府県の単位にする (作り手の判断。上の「地域は都道府県の単位にする」)                                        |
| 家ごはん N 回、N の地域 (区市町村の数)、四季 | 作り手がいらないと判断した                                                                                           |

## 運営が足す仕組み

アプリを出し直さずに、運営の管理画面から実績を足せるようにする。

- 実績は「どの記録を数えるか」×「どう解除するか」× 印、の組み合わせで作る。この組み合わせで表せない実績は、アプリの改修が要る
  - どの記録を数えるか: 種類 (食・飲の大カテゴリを含む)、店、都道府県、家、日時 (日付・時間帯)
  - どう解除するか: 初めて、N 回、N 種類
  - 印: シークレット、期間
- 種類ごと、店ごと、都道府県ごとに、1 つずつ自動で作れるようにする。47 都道府県分を手で作らないため
- 種類は、運営が持つ 3 段の一覧にする (大分類 → 種類 → 細かい種類。[`kinds.md`](kinds.md))。種類を数える実績は、真ん中の「種類」で数える。AI の判定結果をこの一覧に合わせ、実績の定義は一覧の項目を指す。「そば」と「年越しそば」のどちらで数えるか、のような粒度の問題を起こさないため。一覧にないものが入る「その他」は数えない
- 足したら、過去の記録もさかのぼって判定する。さかのぼって解除した分は、保存の流れとは別に 1 回まとめて知らせる。期間付きはさかのぼらない
- 一度解除したら、あとで記録を直しても取り消さない。「取り消す」で記録そのものがなくなったときだけ消す
- 実績の定義はサーバーから配るデータにし、判定は端末で行う。判定は「記録と定義から、何度行っても同じ結果になる処理」にし、`packages/` に置いて共有する。協賛ラリーの景品の判定だけはサーバーで行う
- 電波がなく AI の判定を待っている記録は、判定が済んだあと、次にホームを開いたときに解除を出す
- 日時は撮影した場所の現地時刻で判定する。1 日は朝 5 時で区切り、0 時をまたいだ夜を 1 晩として数える

## PHASE 1 で確かめること

- 実績と、はじめての種類の知らせで、4 週間記録が続くか
- 作り手が運営も兼ねるので、シークレット実績の驚きは PHASE 1 では確かめられない

## 決めていないこと

- 「N 種類」の段階 (種類の一覧の中身が決まってから)
- 酒だけの食事を、回数の実績 (同じ店の回数、別々の店の数) に数えるか。数えると、バーに 100 回通って「住民票を移す日も近い」が出て、飲む回数を称える形になる。酒の種類の回数の段と一緒に、実績の種類を詰めるときに決める
- 2 つめの都道府県では、「はじめての〇〇」と「ちょっとそこまで」(2 都道府県) が同時に解除される。どちらかに絞るか
- 実績のタブの画面の細部 (一旦の形はある)
- 管理画面とサーバーの構成
