# 実績 (続けたくなる仕組み)

> **状態: 合意 (2026-11-26)**。仕組みの形と、最初に入れる実績の一覧まで決めた。

## 目的

記録するたびに、HINAMI 自身が小さな見返りを返す。作り手 1 人で使う PHASE 1 の 4 週間でも効くこと。

## 背景 (作り手の声)

- 続いているのはインスタのストーリーと Locket。気軽に上げられ、上げたあと知り合いからスタンプやいいね、ときどき「どこ?」「おいしそう」の DM が届いて話が広がる。他の人の投稿も見られる
- そこに上げている食: いいレストラン、いいお酒を買ったとき、凝った手料理、おいしい・美しい料理、おしゃれなカフェ
- それらの SNS への不満: 写真を後から見返しづらい、食べた場所が分からない、分類できない
- 「残していくたびに、いろんな実績が解除される仕組みがあると続きそう」。使ったことはなく、どんな実績が効くかは使ってみないと分からない

## 何がいつ返るか

| いつ       | 返るもの                                        | どこで                                                                                           |
| ---------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 記録の直後 | 実績の解除、図鑑への追加                        | HINAMI                                                                                           |
| 記録の直後 | 人からの反応                                    | HINAMI の中のつながっている人と、ストーリーなど今の SNS (撮った写真は端末に残り、そこから上げる) |
| あとから   | 見返す、場所が分かる、分類できる (図鑑・比べる) | HINAMI                                                                                           |

HINAMI の中のつながりは最初の版から入れる。ただし一人で使っても成り立つことが前提 ([`../concept.md`](../concept.md))。

## 実績の形

実績は図鑑の節目として作る。図鑑と実績を別々の仕組みにしない。区分は 2 つで、「隠し」「期間」はどちらにも付けられる印にする。

| 区分              | 何で解除されるか                                                         | 例                                                      |
| ----------------- | ------------------------------------------------------------------------ | ------------------------------------------------------- |
| 初めて (広がり)   | 新しい土地や場面に、初めて出会う                                         | はじめての京都府 (2 つめの都道府県)、はじめての家ごはん |
| 積み重ね (深まり) | 同じものが重なる。最初の段は 2・3・5 回と低く刻む                        | 同じ店に 3 回、ラーメン 3 回、5 軒                      |
| 印: 隠し          | 条件を伏せ、解除されて初めて分かる。一覧には「隠し あと N 個」とだけ出す | 0 時を過ぎたシメ                                        |
| 印: 期間          | 運営が足す季節もの。前もって知らせず、あとで気づく                       | ある年の冬だけの鍋                                      |

- 種類を使う実績は、AI が付けた種類 (ラーメン、日本酒など) で数える。食・飲は種類の上の大カテゴリとして裏で持つ
- 最初の段を低く刻むのは、PHASE 1 の記録は 4 週間で十数件から二十数件と見ており、高い段だけでは 3〜4 週目に何も起きなくなるため
- 店を使う実績は、店が決まった記録だけを数える
- 同じ食事 (時刻と場所でまとまった記録) の中では、同じ種類・同じ店は 1 回と数える。一晩に日本酒を 5 杯記録しても「日本酒 5 回」にはしない

## 図鑑への追加

はじめての種類 (例: 日本酒) と、はじめての地域 (区市町村。家は除く) は、実績にせず、図鑑への追加として保存したときのカードに小さく出す。

- 実績にしないのは、出る回数が多すぎるため。仮の 1 か月 (20 件) で試算すると、記録 1 件につき実績が 2 つずつ出て、その半分がこの 2 つだった
- アプリの「はじめて」は初めて記録しただけで、初めて食べたわけではない。よくある種類ほど「おっ」とならない

## 最初に入れる実績

「〇〇」が入るものは、種類ごと・店ごと・都道府県ごとに自動で作る。

| 区分     | 実績                      | 数え方                                                                              | 段階                     |
| -------- | ------------------------- | ----------------------------------------------------------------------------------- | ------------------------ |
| 初めて   | はじめての〇〇 (都道府県) | 2 つめの都道府県から出す。最初の 1 つは基準の土地なので出さない。帰省先の家も含める | —                        |
| 初めて   | はじめての家ごはん        | 家で撮った食べ物。惣菜や出前も入るので「手料理」ではなく「家ごはん」と呼ぶ          | —                        |
| 積み重ね | 〇〇 (種類) N 回          | 同じ食事の中では 1 回                                                               | 2・3・5・10・25・50・100 |
| 積み重ね | 〇〇 (店) に N 回         | 店が決まった記録。同じ食事の中では 1 回                                             | 2・3・5・10・25・50・100 |
| 積み重ね | N の都道府県              | 家も含める                                                                          | 2・5・10・20・47         |
| 積み重ね | N 種類                    | 記録した種類の数                                                                    | 種類の一覧が決まってから |
| 積み重ね | N 軒                      | 店が決まった、別々の店の数。一晩で回った軒数とは別物                                | 5・10・20・50・100       |
| 隠し     | 朝の一皿                  | 朝 5〜10 時の食べ物                                                                 | —                        |
| 隠し     | 0 時を過ぎたシメ          | 0〜5 時の食べ物                                                                     | —                        |
| 隠し     | 大晦日のそば              | 12 月 31 日のそば。1 日は朝 5 時で区切るので、1 月 1 日の 0 時台も入る              | —                        |

- 時刻を使う実績は、写真の撮影時刻だけで判定する。撮影時刻のない画像 (スクリーンショット、保存した画像) は対象にしない
- 大晦日のそばは毎年の日付の条件で、期間限定ではない。印は「隠し」だけにし、過去の記録へのさかのぼりも効く
- 25・50・100 の高い段は、使い始めて数か月で低い段を出し尽くしたときのために、最初から入れておく。その先は、運営があとから足す実績と年間ふりかえりが担う。実績だけで続けさせようとしない

### 試算

仮の 1 か月 (記録 20 件、東京、店 7 軒のうち 3 軒に再訪) で数えた。記録は想定で作ったもので、実際の数は使ってみないと分からない。

| 週     | 実績 | 図鑑への追加 |
| ------ | ---- | ------------ |
| 1 週目 | 2    | 7            |
| 2 週目 | 4    | 4            |
| 3 週目 | 7    | 3            |
| 4 週目 | 3    | 5            |

どの記録でも、実績か図鑑への追加のどちらかが返る。1 週目は実績が少ないぶん、図鑑への追加が多い。

## 見せ方

ワイヤーフレーム: [`recording-flow.html`](recording-flow.html) の「A. その場で撮る」の保存後。

```
保存したときのトースト
┌──────────────────────────┐
│ 残しました · 麺屋 ひかり   取り消す │
│ スタンプ  5 軒                     │
│ 図鑑  渋谷区 を追加                │
└──────────────────────────┘
```

- 解除の知らせと図鑑への追加は、保存したときの「残しました」のトーストに一緒に出す。タップは増やさない
- 比べる 1 問は、このトーストと同時に出さない。トーストが消えてから、ホームのカードで出す ([`compare.md`](compare.md))
- 「取り消す」を押したら、解除の知らせも一緒に消える
- 解除した実績と進み具合は、実績のタブで見る。タブの中では、実績を「スタンプ」と呼ぶ ([`navigation.md`](navigation.md))。ホームに「あと 2 回」のような表示は出さない
- 実績のタブは、ゲームの実績やスタンプラリーのように、1 種類のスタンプだけで見せる (作り手の判断。「埋めていきたい」「解除していきたい」と思えるように)。押したスタンプは塗りつぶし、進行中のものは周りの輪で進み具合、ひみつは「?」。段階のある実績は 1 つのスタンプにまとめ、タップするとボトムシートで段ごとの枠が並ぶ (作り手の判断)。都道府県は 47 の枠を埋めていく。画面は一旦この形で、スタンプの種類 (どの実績を置くか、並べ方の分け方) はあとで詰める ([`achievements-flow.html`](achievements-flow.html))

## 入れないもの

| もの                                         | 理由                                                                                                                 |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 連続日数                                     | 義務感は逆効果 (前提)                                                                                                |
| 総件数 (「50 件記録」)                       | 覚えておきたくない食まで記録させてしまう                                                                             |
| 杯数・軒数を伸ばすもの (「一晩で 3 軒」)     | 過度の飲酒を勧めるアプリは App Store の審査ガイドライン 1.4.3 で禁止されている。量ではなく、種類や土地の広がりで作る |
| 前もって知らせる期間限定                     | 取り逃したくない気持ちが義務になる。STEP 2 の協賛ラリーは、告知する別の仕組みとして分ける                            |
| はじめての種類・地域 (実績として)            | 出る回数が多すぎる。図鑑への追加として出す (上の「図鑑への追加」)                                                    |
| 家ごはん N 回、N の地域 (区市町村の数)、四季 | 作り手がいらないと判断した                                                                                           |

## 運営が足す仕組み

アプリを出し直さずに、運営の管理画面から実績を足せるようにする。

- 実績は「どの記録を数えるか」×「どう解除するか」× 印、の組み合わせで作る。この組み合わせで表せない実績は、アプリの改修が要る
  - どの記録を数えるか: 種類 (食・飲の大カテゴリを含む)、店、地域・都道府県、家、日時 (日付・時間帯)
  - どう解除するか: 初めて、N 回、N 種類
  - 印: 隠し、期間
- 種類ごと、店ごと、都道府県ごとに、1 つずつ自動で作れるようにする。47 都道府県分を手で作らないため
- 種類は、運営が持つ 3 段の一覧にする (大分類 → 種類 → 細かい種類。[`kinds.md`](kinds.md))。種類を数える実績は、真ん中の「種類」で数える。AI の判定結果をこの一覧に合わせ、実績の定義は一覧の項目を指す。「そば」と「年越しそば」のどちらで数えるか、のような粒度の問題を起こさないため。一覧にないものが入る「その他」は数えない
- 足したら、過去の記録もさかのぼって判定する。さかのぼって解除した分は、保存の流れとは別に 1 回まとめて知らせる。期間付きはさかのぼらない
- 一度解除したら、あとで記録を直しても取り消さない。「取り消す」で記録そのものがなくなったときだけ消す
- 実績の定義はサーバーから配るデータにし、判定は端末で行う。判定は「記録と定義から、何度行っても同じ結果になる処理」にし、web とネイティブで共有する (`packages/`)。協賛ラリーの景品の判定だけはサーバーで行う
- 電波がなく AI の判定を待っている記録は、判定が済んだあと、次にホームを開いたときに解除を出す
- 日時は撮影した場所の現地時刻で判定する。1 日は朝 5 時で区切り、0 時をまたいだ夜を 1 晩として数える

## PHASE 1 で確かめること

- 実績と図鑑への追加で、4 週間記録が続くか
- 作り手が運営も兼ねるので、隠し実績の驚きは PHASE 1 では確かめられない

## 参考にした事例

| 事例         | 型                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------- |
| Untappd      | 段階のあるバッジと、期間限定のバッジ                                                          |
| Steam / Xbox | 隠し実績は条件を伏せ、残りの数だけを見せる                                                    |
| ポケモン GO  | 種類ごとのメダルを、銅・銀・金・プラチナの段階で刻む                                          |
| Apple Watch  | 反面教師。期間限定のアワードは、その日に運動しないと取れない (前もって告知する期間限定の典型) |

## 決めていないこと

- 「N 種類」の段階 (種類の一覧の中身が決まってから)
- 実績のタブの実績の画面の細部 (一旦の形はある) と、マップの画面
- 「図鑑への追加」の言い方。実績のタブから種類をなくし、地域はマップにしたため、はじめての種類・地域をどう知らせるかを見直す
- 管理画面とサーバーの構成
