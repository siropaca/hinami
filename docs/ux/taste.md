# 記録が好みを語る (UX)

> **状態: 方針を決めた (2026-11-28)**。最先端の事例と手法の調査から採った施策 3 ([`../research/2026-11-28/README.md`](../research/2026-11-28/README.md))。どの場面で好みを返すか (選ぶとき、ふりかえるとき、残した直後など) は、データをためながら、作りながら確かめる (2026-11-28、作り手の判断)。根拠の調査は [`../research/2026-11-28/discovery.md`](../research/2026-11-28/discovery.md)。

## 目的

記録の傾向から、自分の好みを言葉にして返し、次に試すものに出会えるようにする。「使う (次の一皿・一杯を選ぶ)」を、自分の記録で支える。

## 背景 (作り手の声)

- 同じ店に何度も行くことはあまりない。何度も行く店は、提案してもらわなくてもいい
- それより、記録の傾向を分析したり、新しいところやものを提案してくれたりするほうがうれしい
- ただし、まだ行っていない店の提案は、少なくとも MVP には入れない

## 出すもの

| もの         | 決まり                                                                                                                                                                                                                                                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 好みのことば | 種類ごとに、気持ち (大好き、好き、合わなかった。食事の気持ちも) と、比べた順番、名前、メモを照らし、好みの共通点を 2〜3 文にする (例: 「上位のラーメンは、魚介の清湯が多いようです」「上位のコーヒーは、浅煎りに寄っているようです」)。言葉は、です・ます調でやわらかく書き、決めつけない。文ごとに根拠の記録を並べ、「違う」で消せる |
| 確からしさ   | 気持ちの数が足りない種類には、確からしさの低い下書きとして出す。いろいろな種類を少しずつ食べる人を置いていかないため                                                                                                                                                                                                                  |
| 次に試す方向 | 種類ごとに 2 つだけ出す。近い方向を 1 つ、いつもと違う方向を 1 つ。銘柄や店の名前ではなく、方向 (系統、産地、造り、焙煎など) で出す。理由に自分の記録を添える。試したものは除く                                                                                                                                                       |

## 提案の作法

どの提案にも通す。あとで提案を足すとき (店の提案、友だちとの好みの一致度など) も同じ。

- 理由と、根拠にした自分の記録を見せる
- 記録済みのものは除く
- 「いつもと違う」を 1 つ混ぜる。おすすめに頼るほど幅が狭くなるため (Anderson ほか、WWW 2020)
- 「この記録は好みに入れない」で直せる。好みのことばも「違う」で消せる
- 通知で押さない
- 協賛を混ぜない。広告に見えるため
- からかう口調や決めつけをしない (AI がからかう口調でまとめて取り下げた例、根拠の見えない決めつけに反発した例がある)
- 飲む量ではなく、広がりだけを勧める (App Store の審査ガイドライン 1.4.3)
- 特定の種類に寄せない。LLM の知識はワインに厚いので、種類ごとに当たり方を確かめる

## 前提

- 家の品にも気持ちを聞き、ランキングに入れる。家で食べたパンや家ごはんの気持ちも残さないと、好みの材料が集まらないため ([`recording.md`](recording.md) の「場所」)
- 名前が残るほど、材料が厚くなる ([`history.md`](history.md) の「名前の候補」)

## PHASE 1 で確かめること

画面は作らない。

- 2 週目と 4 週目に記録を書き出して LLM に読ませ、好みのことばと次に試す方向を出す
- 作り手が「当たっているか」「選び方が変わったか」を付け、出した方向を 4 週間のうちに試したかを数える
- 気持ちの数のしきい値に、どの種類が届くかを数える
- 端末のモデルと外部の AI の出来を比べる。端末のモデルは無料でオフラインでも動くが、一般の知識が薄い。外部の AI を使うなら、名前やメモを送るので同意が要る
- 作り手と家族だけでは、ふたりが記録しない種類の当たり方は測れない。種類ごとの当たり方は限定テストで測る

## 入れないもの

| もの                                    | 理由                                                                                                                                                   |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| まだ行っていない店の提案                | MVP に入れない (作り手の判断)。店を当てるには大勢の評価か外部の店の情報が要る ([`../research/2026-11-28/places.md`](../research/2026-11-28/places.md)) |
| 方向から地図アプリの検索を開く          | 店の提案の一種として、MVP に入れない                                                                                                                   |
| 何度も行く店を勧める (前回のこの店など) | 同じ店に何度も行くことはあまりなく、提案されなくてよい (作り手の判断)                                                                                  |
| 好みの近い友だちの上位を見せる          | 友だちに順位を見せるかを新しく決める必要がある。限定テストのあとに考える                                                                               |

## 決めていないこと

- 好みのことばと次に試す方向を、どの場面で、どこに出すか (画面)。データをためながら、作りながら確かめる (2026-11-28、作り手の判断)
- どの LLM で出すか (端末、Apple のサーバーのモデル、外部の AI)
- 気持ちの数のしきい値
