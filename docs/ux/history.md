# 履歴と検索 (UX)

> **状態: 合意 (2026-11-26)**。タブの形と、食事の詳細まで決めた。「案」はもうない。
>
> タブの名前は「記録」にした (2026-11-27)。この文書では、機能の名前として「履歴と検索」と書く。同じ日に、マップをこのタブの中に移した (下の「マップ」)。
>
> ワイヤーフレーム: [`history-flow.html`](history-flow.html)。ブラウザで開く。

## 目的

今までの飲食を、いろんな角度で探せるようにする。検索性はこのアプリの売りにする ([`../concept.md`](../concept.md))。

## 背景 (作り手の声)

- 探したくなる場面: 最近飲んだ日本酒で美味しかったのはなんだっけ / 今年はどんな日本酒を飲んだっけ / 今年はどれだけレストランに行ったっけ / この前美味しかったレストランはどこだっけ / 先月はどれだけ記録したっけ
- カレンダー、種類 (ジャンル) での絞り込み、フリーワード検索があれば、どれかで見つけられる
- 「美味しかった」は、最近のその種類を出せば写真を見て分かる。店の好きな順は要らない
- 検索の一覧は食事単位がよい。複数の品があればサムネイルで見られる

## 形

記録のタブ 1 つで、カレンダーと検索とマップを兼ねる。絞っていないときはカレンダー、種類か言葉で絞ったら食事単位の一覧に切り替える。カレンダー・一覧とマップは、切り替えで行き来する (下の「マップ」)。

```
絞っていないとき (カレンダー)
┌───────────────────────────┐
│ [ 店名・メモ・地域で検索         ] │
│ [すべて] [日本酒] [ラーメン] [▾]   │
│ [カレンダー | マップ]              │  ← 見方の切り替え
│ ‹ 2026 年 11 月 ›                  │
│ 記録 18 件 · 外食 9 回 · 7 軒      │
│ 日 月 火 水 木 金 土              │
│ ▢3 ▢  ·  ▢2 ·  ▢  ▢             │  ← その日の 1 枚と件数
└───────────────────────────┘

日本酒で絞ったとき (食事単位の一覧)
┌───────────────────────────┐
│ [日本酒 ×]           日本酒 26 件  │
│ 11 月                              │
│ 11/21 鮨 はやし   ▣ ▢ ▢           │  ← 合う品を先頭に、印を付ける
│ 11/08 家          ▣               │
│ 10 月                              │
│ 10/30 バー 灯     ▣ ▢             │
└───────────────────────────┘
```

| 項目             | 決まり                                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| タブ             | 記録のタブ 1 つ。検索もマップも別のタブにしない。カレンダー・一覧・マップ・種類・フリーワードは同じ記録の見方の違いで、絞り込みを共有できるほうが自然なため          |
| 見方の切り替え   | カレンダー (絞ったときは一覧) とマップを切り替える。はじめはカレンダーで開く。切り替えても、絞り込みと言葉は残る                                                     |
| カレンダー       | 絞っていないときの最初の画面。日付ごとに代表の写真 1 枚と件数を出す。代表はその日最後の食事の 1 枚目                                                                 |
| 日付をタップ     | その日の記録を食事ごとに出す                                                                                                                                         |
| 種類で絞る       | 種類のボタンはよく記録する種類から並べ、▾ で 3 段の一覧から選べ、細かい種類 (醤油ラーメンなど) でも絞れる ([`kinds.md`](kinds.md))。絞ると食事単位の一覧に切り替える |
| フリーワード     | 探す先はメモ、店名、地域名、種類名。ひらがな・カタカナ・全角半角・長音の違いはそろえて探す。入れると食事単位の一覧に切り替える                                       |
| 一覧の単位       | 食事。日付、場所、品のサムネイルを並べる。絞り込みや言葉に合う品を先頭にし、印を付ける。新しい順で、月の見出しを付ける                                               |
| 一覧の範囲       | 期間で区切らず、新しい順にすべて出す。月の見出しで区切る。「今年どんな日本酒」は、日本酒で絞って今年の分を見る                                                       |
| まとめ           | 月の見出しに「記録 N 件 · 外食 N 回 · N 軒」を出す。外食は食事単位で数え、家は数えない。店が決まっていない食事は回数に入れ、軒数には入れない                         |
| 何もないとき     | 記録が 0 件のときは、記録の入り口へ案内する。絞り込みや言葉に合う記録がないときは、そう出して、絞り込みや言葉を外せるようにする                                      |
| 電波がないとき   | 検索は端末の中で動く。電波がなく AI の判定がまだの記録は、種類では見つからない                                                                                       |
| 店の好きな順     | 持たない                                                                                                                                                             |
| ランキングの入口 | 種類で絞ったときだけ、一覧の上にその種類のランキングの入口を出す。比べる相手がいないうちは出さない ([`compare.md`](compare.md))                                      |

## マップ

記録のタブの中で、カレンダー (絞ったときは一覧) と切り替えて見る (2026-11-27、作り手の判断。[`navigation.md`](navigation.md))。ワイヤーフレーム: [`history-flow.html`](history-flow.html) の「D. 地図で見る」。

| 項目               | 決まり                                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| ピン               | 食べた場所にピンを立てる。数字はその場所の回数。近いピンは、縮めるとまとまる                                                         |
| 店が決まっていない | 地域のあたりにピンを置く                                                                                                             |
| 家                 | 自分のマップには出す (自分にしか見えない)                                                                                            |
| 絞り込み           | 種類や言葉で絞ると、合う食事のピンだけを出す。切り替えても、絞り込みと言葉は残る                                                     |
| 期間               | 区切らない。カレンダーの月とは連動しない                                                                                             |
| 開いたときの範囲   | 毎回、現在地を中心に、近くのピンが見える広さで開く (作り手の判断)。位置情報が使えないときは、すべてのピンが入る範囲で開く            |
| ピンをタップ       | ボトムシートで、その場所で食べた日の一覧を出す。一覧と同じ形 (日付、場所、写真) (作り手の判断)。絞っているときは、合う食事だけを出す |
| 食事をタップ       | 一覧から開くときと同じ食事の詳細                                                                                                     |

- マップを別のタブにしない理由は [`navigation.md`](navigation.md) にまとめた

## 名前の候補 (確認カードのメモ)

AI が写真の文字 (ラベル、メニュー、包装、黒板) から名前 (銘柄、品名、メニューの名前) を読めたときは、メモの欄に候補として出し、タップで入れられるようにする (詳細は [`recording.md`](recording.md))。どの種類の品でも同じ扱いにする (2026-11-28。[`../research/2026-11-28/README.md`](../research/2026-11-28/README.md) の施策 2「どの品も、名前まで残る」)。

- 撮ったら残る形なので、確認カードを開かずに残した品も多い。そうした品も、食事の詳細を開いたときに写真から読み直して、候補を出す
- 品には、名前を読むための 2 枚目 (ラベル、札、包装) を足せる。瓶とグラスを撮っても、品は 1 つのまま
- 入れなかった候補は持たない。ただし「見送った」という印は持ち、同じ候補を毎回出さない
- 比べるとランキングでは、品を「名前 → 店 → 日付」の順に示す ([`compare.md`](compare.md))。記録のタブの一覧は食事単位のまま

- 「あの日本酒なんだっけ」に名前で答えられ、名前で検索もできるようになる
- 専用の「名前」の欄を作らず、メモへの候補にするのは、そのほうが汎用的なため (銘柄、品名、メニューの名前など何でも入る)
- 入れなかった候補は持たない。写真の文字を見えないところに持つと、背景のレシートや人の名前まで入ってしまうため
- 候補を入れたときは、読み (例: だっさい) も一緒に持って検索に使う
- 文字を読めるかは、PHASE 1 で確かめる。縦書きの酒のラベル、横書きのラベル、包装、手書きの品書きに分けて測る。縦書きや毛筆は端末では読めない見込みで、同意を取って外部の AI に回す道を残す

## 実績のタブとの分担

種類で探すのは記録のタブだけにし、実績のタブには種類の一覧を置かない。同じ一覧を 2 か所に作らないため (理由は [`navigation.md`](navigation.md))。

## 食事の詳細

記録を保存したあとに見返し、直す場所。確認カードと同じ形で直せるので、直し方を新しく覚えなくてよい。

ここでは出す要素だけを決める。写真の大きさや並べ方などの見た目は、デザインのフェーズで決める (2026-11-27、作り手の判断)。

| まとまり | 要素       | 決まり                                                                                                                                                                         |
| -------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 食事     | 日時       | その食事の最初の品を撮った日時                                                                                                                                                 |
| 食事     | 場所       | 店・家・地域名。食事ごとにまとめて直し、選んだ場所は同じ食事の品すべてに入る。店が決まっていないときは「道玄坂 · 候補 3 件」のように出し、タップで確認カードと同じ候補から選ぶ |
| 食事     | シェア     | 友だちがいるときだけ出す。食事ごとに「自分だけ / 友だち」を変えられる ([`connect.md`](connect.md))                                                                             |
| 食事     | 反応       | 友だちから届いたスタンプとメッセージ。届いたときだけ出す。タップすると、その人とのスレッドに移る                                                                               |
| 食事     | 食事を消す | 消す前に確かめる                                                                                                                                                               |
| 品       | 写真       | 品ごとに 1 枚。名前を読むための 2 枚目 (ラベル、札、包装) を足せる                                                                                                             |
| 品       | 種類       | 3 段の真ん中の「種類」(ラーメン、日本酒など)。1 枚に複数あれば複数 ([`kinds.md`](kinds.md))                                                                                    |
| 品       | メモ       | 書いていなければ、ここから書き足せる                                                                                                                                           |
| 品       | 品を消す   | 品をタップして開く、確認カードの形の画面から消す。消す前に確かめる                                                                                                             |

- 開き方: ホーム、記録のタブの一覧、その日の食事、マップの場所の一覧から、食事をタップする
- 品をタップすると、確認カードと同じ形で種類とメモを直せる
- 品は撮った順に並べる。食事の流れ (はじめの一品から締めまで) のまま見返せるため
- 比べるの順位と、実績の進み具合は出さない。順位はランキング、実績は実績のタブで見る。食事の詳細は見返すことと直すことに絞る
- 友だちの食事の詳細に出す要素は [`connect.md`](connect.md) で決めている (写真とメモ、だれといつ)

## 決めていないこと

- 年単位で見る画面 (「今年はどれだけ」)。一旦入れない。入れるなら、12 か月のカレンダーに月ごとの件数を出し、月をタップすると絞り込みを残したまま月のカレンダーに移る形が候補。そのときは、絞ったら一覧に切り替える今の決まりと合わせて考え直す
