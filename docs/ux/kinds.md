# 種類の一覧 (UX)

> **状態: 合意 (2026-11-27)**。3 段の持ち方、どの段を何に使うか、一覧の作り方を決めた。一覧そのもの (どの種類を入れるか) は、アプリを作るときに作る。

## 目的

AI が付ける「種類」の持ち方を決める。比べる (ランキングの相手)、実績 (〇〇 N 回)、記録のタブの絞り込みが、すべてこの一覧の上に乗る。

## 3 段で持つ

```
大分類 (裏で持つ)   種類 (ふだん見せる)     細かい種類 (AI が分かれば付ける)
麺            →    ラーメン          →    醤油ラーメン、味噌ラーメン、つけ麺
              →    そば              →    ざるそば、天ぷらそば
酒            →    日本酒            →    純米大吟醸、純米酒
              →    ワイン            →    赤、白、スパークリング
肉            →    焼き鳥、焼肉 …
```

| 段         | 例                       | 使うところ                                                                                                                                                                                        |
| ---------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 大分類     | 麺、酒、肉               | 裏で持つ。絞り込みの ▾ の見出しに使う。実績のまとまり分けにも使う候補 (実績の種類と一緒に決める)。確認カードには出さない。食・飲は、さらにその上の裏の区分                                        |
| 種類       | ラーメン、日本酒、焼き鳥 | ふだん見せる段。確認カード、記録のタブの絞り込みのボタン、ランキング (比べる相手)、実績 (〇〇 N 回、N 種類) はこの段にそろえる                                                                    |
| 細かい種類 | 醤油ラーメン、純米大吟醸 | AI が見分けられれば付けておく。記録のタブの絞り込みの ▾ から選べる。ランキングと実績には使わない。比べるの相手を選ぶときだけ使う (細かい種類が同じ品を先に相手にする。[`compare.md`](compare.md)) |

- 「ラーメン」くらいの粒度が、比べる相手として自然 (作り手も同じ感覚)。「麺」だとラーメンとそばを比べることになり、「醤油ラーメン」だと相手が少なすぎてランキングが育たない
- 細かい種類は見分けられないことも多いので、見分けられなくても困らない段に置く
- 一覧は運営が持ち、管理画面から足せる ([`achievements.md`](achievements.md) の「運営が足す仕組み」)

## 一覧の作り方

```
AI が見分けた
 ├─ 一覧にある  → その種類を付ける (ラーメン)
 └─ 一覧にない  → 近い大分類の「その他」に入れる (麺 (その他))
                  運営の管理画面に「一覧にない候補」として集まる
                  運営が足したら、過去の記録も付け直す
```

| 項目           | 決まり                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 最初の一覧     | 網羅を目指し、できるだけ多く用意する (作り手の判断)。AI が見分けにくい種類も入れる。手で直すときに一覧から選べるようにするため                               |
| 一覧にないもの | AI が一覧にないものを見つけたら、近い大分類の「その他」に入れる。確認カードには「麺 (その他)」のように出す。AI が見立てた名前は裏に残し、付け直しに使う      |
| その他の扱い   | 中身がばらばらなので、ランキング (比べる相手) と実績には使わない                                                                                             |
| 運営が足す     | 管理画面に「一覧にない候補」が集まる。運営が種類を足したら、その他に入っていた過去の記録も付け直す。付け直しで解除した実績は、1 回まとめて知らせる           |
| 利用者が選ぶ   | 確認カードの ▾ で、一覧の中から探して選ぶ。一覧になければ「その他」を選ぶ。新しい種類は作れない (利用者に分類を登録させない。[`recording.md`](recording.md)) |
| PHASE 1        | 作り手が運営も兼ねる。自分の記録で「その他」に入ったものを見ながら足していく                                                                                 |

- 最初からできるだけ多く用意するのは、「その他」を減らすため。その他に入った分は、運営が足すまでランキングにも実績にも乗らない
- 一覧にないものを捨てずに「その他」に入れ、AI の見立てを残しておけば、あとで足したときに過去の記録まで付け直せる。実績の「足したら過去の記録もさかのぼって判定する」([`achievements.md`](achievements.md)) と同じ考え

## 決めていないこと

- 一覧そのもの (どの種類を、どの段に入れるか)。アプリを作るときに、サーバーに置くデータとして作る。画面の流れは中身で変わらず、数百件をドキュメントで下書きすると同じものを 2 回作ることになるため。「つけ麺」をラーメンの細かい種類にするか別の種類にするか、のような境目は、そのとき作り手が見る
- 「N 種類」の実績の段階 (実績の種類と一緒に決める)
